## 二、排版主线清单

### 2.1 愿景锚点

> 老师用「对象树 / 装盒子 / 套样式 / 调文档模板」组卷排版；Typst 负责公式、分页、PDF。  
> **对齐教辅向 InDesign 的真实用法**（框 + 样式 + 栏 + 母版），**不做通用 InDesign**（自由钢笔、任意图层、绕排等）。

教辅向 InDesign ↔ 本产品对照：

| 教辅向 InDesign | 本产品 |
|-----------------|--------|
| 文本框 / 题组框 | `PubBlock`（题、节、盒） |
| 对象样式 | `style_sets` / `box_style`（声明式 `variant`，禁止编辑态自由路径） |
| 母版 / 文档设置（页眉页脚页码、栏、边距） | `doc.page` → `LayoutSpec` + profiles |
| 钢笔描花边（模板期画一次） | 皮肤库登记；用户只套样式 |
| JS 灌题 / 批处理 | 试题篮装配 + `PublicationDocument` 编译 |

### 2.2 分期

| 阶段 | 目标 | 交付物 |
|------|------|--------|
| **P0**（当前） | 子系统边界 | 本文档；`PublicationDocument` IR；独立 `/studio` 壳；试题篮入口接入 |
| **P1** | 可编辑结构 + 性能纪律 | 对象树选中；HTML 工作画布（点选 + **块级虚拟化**）；中栏编辑/校对 Tab；右栏「文档模板 \| 对象」骨架 |
| **P2** | 容器化与双端皮肤 | `MultiColumnBox` 插入/移除；样式集保存/套用；`typst_gen` 映射同名皮肤；双端登记约定 |
| **P3** | 文档种类与母版扩展 | `kind`: exam / handout / topic；文本块、封面块；底色/水印/品牌页眉等文档模板字段按需落地 |
| **P4** | 持久化 | 排版文档存库 / 本地；与 `papers` 可选关联 |
| **P5+**（可选） | 增强 | 结构态默认长卷、片段 mark、typst.ts、模板市场、缩略小地图（简化 Canvas） |

### 2.3 P0～P2 详细主线（执行优先级）

1. **`PublicationDocument` IR**（前端类型 + 文档契约；后端可后置）  
2. **`/studio` 沉浸式工作台**（三栏壳：树 / 画布|预览 / 文档模板·对象属性）  
3. **试题篮 → Studio**（sections → Document 装配）  
4. **对象树只读 → 可排序**（树可虚拟滚动）  
5. **工作画布（HTML，虚拟化）与 Typst 校对预览切换**（校对只挂当前页 SVG）  
6. **`MultiColumnBox` + 样式集**（HTML 皮肤 + Typst 同名函数）  
7. **`LayoutDoc` / `typst_gen` 增加容器块与皮肤映射**  
8. **导出 PDF 吃 PublicationDocument 编译结果**

### 2.4 明确不做（主线外）

- 自由画框、钢笔路径描边、复杂绕排、图层  
- 字符级任意选中改样式（P5 前不做）  
- 新建切断题库的独立 Git 仓库 / 独立后端  
- 解冻 Word 格式 parity  
- **整卷 HTML + 全量 KaTeX 常驻 DOM**（150～200 页教师讲义场景下会卡死）  
- **Canvas / WebGL 作为主编辑画布**（公式与 `LatexRender` 复用成本高；本产品是结构化块编辑，非自由画布）  
- 前端任意 CSS / 无法映射到 Typst 的「一次性皮肤」

## 三、交互模型与双层模板

### 3.1 交互状态机（产品口径）

- **唯一可写真相源**：`PublicationDocument`；画布不存第二套坐标。  
- **主路径**：选中对象 → 套样式集 / 装进多栏盒 / 拆盒 / 排序；未选中或进入「版面」→ 调文档模板参数。  
- **公式编辑**：默认不在排版画布内改 LaTeX；题面仍引用 `question_id`，改公式走录题链路。  
- HTML 画布 = 可交互的结构与皮肤投影；Typst = 印刷与分页真相。

### 3.2 双层模板

| 层 | 职责 | 数据 |
|----|------|------|
| **文档模板（母版）** | 页码、页眉页脚、纸张/边距、全局栏数与栏间距、首页/正文差异、字体、全局底色/水印/品牌页眉（扩展） | `doc.page` → 现有 `LayoutSpec`（`frontend/src/api/types/layout.ts`）+ `/typeset/profiles` |
| **对象样式（盒子皮肤）** | 题/盒外框：侧签、顶徽章、花角线框、底色卡片等 | `style_sets[]`、`style_set_id`、`box_style` |

- Studio 右栏：**文档模板**（版面）与 **对象属性** 分开；勿把页眉页脚参数塞进单题皮肤。  
- **全局栏**（`page.columns` + `margins.gutter_mm`）与 **盒内栏**（`multi_column_box.columns`，P2 起可加 `column_widths`）**并存**，旋钮不混用。  
- 母版在画布上的投影（页眉/页脚/水印区）可点进「文档模板」，**不可**当正文块随意拖拽改几何。

### 3.3 HTML ↔ Typst 视觉一致（几乎同款）

> 备选优化路径：[结构化排版_档B_Typst视觉单源与热区.md](结构化排版_档B_Typst视觉单源与热区.md)（视觉单源 = Typst；显式启用前以本节双端口径为准）。

```
StyleSet + LayoutSpec（单一契约）
        ├─→ HTML 皮肤组件（Studio 编辑画布）
        └─→ typst_gen 皮肤/母版函数（SVG 校对 / PDF）
```

| 目标 | 口径 |
|------|------|
| 版心、边距、栏、盒皮、色、圆角、页眉页脚 | **几乎一致**（共享 token / mm；网页加载与导出同系字体，优先思源宋/黑） |
| 分页切口 | **以 Typst 为准**；HTML 编辑态可为连续流 + 虚拟列表 |
| 公式 | 同源 LaTeX；画布 KaTeX、导出 mitex→Typst；**不承诺**字形级一致；失败两侧同规则预检 |

纪律：

- 新皮肤必须 **HTML + Typst 同时登记**；禁止只改一端。  
- 禁止无法映射到 Typst 的自由 CSS 作为可保存样式。  
- 改结构/样式后校对 Tab debounce 重编（沿用现有预览节奏）。

### 3.4 长文档与 DOM 性能（硬需求）

教师讲义可达 **150～200 页**（含多解解析）。卡顿主因是 **KaTeX 公式 DOM 膨胀**，不是「页框个数」。

| 规则 | 要求 |
|------|------|
| 禁止 | 整卷 HTML + 全量 KaTeX 一次挂进 DOM |
| HTML 画布 | **块级虚拟列表**（仅视口 ±N）；公式 IntersectionObserver / `requestIdleCallback` 懒渲染；滚出可销毁子树 |
| 长卷体验 | 允许 **结构态**（题号/盒轮廓/徽章，不全文 KaTeX）与选中邻域 **内容展开** |
| Typst 校对 | **只挂当前页 SVG**（与 `TypesetPreview.vue` 一致） |
| 对象树 | 可虚拟滚动；**IR JSON 全量持有**，与 DOM 规模脱钩 |
| 主编辑技术 | HTML + 现有 `LatexRender`；不以 Canvas/WebGL 作主编辑面 |

性能验收口径（P1 起）：一屏内 DOM/公式量与总页数近似无关；200 页文档下结构编辑可滚动、可点选，不因全量渲染卡死。

## 四、PublicationDocument 设计

编辑态真相源；**不是** Typst 源码，也不是最终 `LayoutDoc`。

### 4.1 与现有层的关系

```
题库 Question
    ↓ 引用
PublicationDocument（Studio 编辑 / 可持久化）
    ↓ compile
ExamRequest + 容器展开 或 直接 LayoutDoc
    ↓
typst_gen → PDF / SVG
```

| 层 | 职责 |
|----|------|
| `ExamBundle` | 内容装配（题面、答案） |
| **`PublicationDocument`** | 结构、顺序、容器、样式集、**文档模板（page）** |
| `LayoutDoc` | Typst 可渲染块序列 |
| `LayoutSpec` | 纸张/边距/页眉等（嵌在 Document.page） |

### 4.2 顶层结构（契约）

见前端：`frontend/src/types/publication.ts`（与本文同步；下文「计划字段」可先于 TS 落地）。

要点：

- `kind`: `exam` | `handout` | `topic`（可扩展，不加自由文档）  
- `body`: 有序 `PubBlock[]`（线性，容器内嵌 children）  
- `style_sets[]`: 可复用对象皮肤  
- `page`: **文档模板**；对齐现有 `LayoutSpec`（纸张、`columns`、`margins`、`header_footer`、`parent_pages`、`fonts`、`color` 等）；后续可扩底色 / 水印 / 品牌页眉  
- `export`: mode、答案开关等（对齐 `ExportMode` / options）

### 4.3 块类型（V1）

| `type` | 说明 | P0 | P2 |
|--------|------|----|----|
| `section` | 大题标题 | ✅ | |
| `question` | 引用 `question_id` + 可选分值/覆盖 | ✅ | |
| `rich_text` | 说明/导语 | 预留 | ✅ |
| `multi_column_box` | 局部多栏容器 | 预留结构 | ✅ 交互 |
| `callout` | 教师提示（可后置） | 预留 | |

### 4.4 容器规则

- 插入盒子：选中多个 block id → 包进 `multi_column_box.children`  
- 移除盒子：children 展开回父级原位；**不删题目**  
- 盒子样式：内联 `box_style` 或 `style_set_id`  
- 全局 `page.columns` 与盒子内 `columns` **并存**（整卷 vs 局部）  
- P2 起盒子可声明 `column_widths`（如左题右笔记比例）；与全局栏旋钮分离  

### 4.5 对象皮肤 `BoxStyle`（计划契约）

在现有颜色/圆角/标题字段上，文档约定增加（实现时写入 `publication.ts`）：

- `variant`: `frame` | `side_tab` | `badge_top` | `ornate_corner` | …（有限枚举，双端登记）  
- 侧签/徽章方位等参数随 variant 解释  
- **禁止**把任意 CSS 字符串存进可持久化样式  

每个 `variant` ↔ 一个 Typst 皮肤函数 + 一个 HTML 主题组件。

### 4.6 编译口径（P2）

1. 线性展开 `body`；遇盒子则生成带皮肤的容器（`#block` / `#columns` / `#grid`）  
2. `question` 块经现有 assembler 取题面；有 `style_set_id` 则外包对应皮肤  
3. `page` + `export` → 现有 `resolve_spec` / `ExamRequest` 路径（母版页眉页脚页码走现有 typst 母版）

## 五、独立 `/studio` 路由

| 项 | 约定 |
|----|------|
| 路径 | `/studio`（可带 query `?from=basket`） |
| meta | `immersive: true`（隐藏系统侧栏） |
| 入口 | 试题篮「排版预览」；日后工作台「排版工作台」 |
| 兼容 | `/basket/typeset` → redirect `/studio` |
| 数据 | `sessionStorage` 键 `studio_document`（JSON）或由 basket sections 现场装配 |

壳布局：

```
┌──────────────────────────────────────────────────────────┐
│ 顶栏：返回 | 标题 | kind | 导出 PDF                         │
├──────────┬───────────────────────────┬───────────────────┤
│ 对象树    │ 中栏 Tab：                  │ 右栏：              │
│ (可虚拟   │  · 编辑 = HTML 画布（虚拟化） │  · 文档模板（版面）   │
│  滚动)   │  · 校对 = Typst 当前页 SVG  │  · 对象属性（选中时） │
└──────────┴───────────────────────────┴───────────────────┘
```

- P0：中栏以 Typst 预览为主。  
- P1 起：编辑 Tab 为 HTML 工作画布（点选 + 虚拟化）；校对 Tab 保持单页 SVG。
