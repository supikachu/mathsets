# 全自动解析质量评估 — 评测规则

> 本文是评测脚本 `scripts/bench_eval_quality.py` 的语义说明。脚本按本文打规则分，不调用 LLM，不改代码、不改 `docs/rules-prompts.md`。
>
> 配套：`docs/全自动解析质量评估_需求分析.md`（为何评、失败后改哪）。
>
> 版本：v1.2 · 2026-08-28

---

## 1. 评什么、不评什么

**事实源**是 MinerU 的 `paper.md`。`full.json`（全自动）和 `export.json`（站外模型）都是对这份 Markdown 的结构化候选，任何一边都可以错。

**评：** 切题是否完整、选择题结构、答案字母/叶子答案、解答题 `parts` 树、教辅杂质、JSON 契约。

**不评：** 文笔、解析是否更好懂、知识点/章节/方法标签、难度、耗时、token。

**不做：** 保真分（是否改写原文）本期脚本不跑；裁判禁止自动改正则或提示词。

---

## 2. 输入文件

每个试卷目录（`bench/eval/<试卷名>/`）需要：

| 文件 | 角色 |
|------|------|
| `paper.md` | 卷面事实（必须） |
| `full.json` | 全自动结果：`{questions:[{question_no, display_order, parsed}]}`（必须） |
| `export.json` | 站外结果：`{questions:[...]}` 或题目数组（**可缺**） |

缺 `paper.md` 或 `full.json`、或 `full.json` 无法解析 → 整卷记 `import_failure`，不算全自动回归失败。

缺 `export.json` → **不**记 `import_failure`。仍评全自动相对 `paper.md`，站外侧各桶为 `na`，分流不计 `export_missed_prompt`。跨卷 `report_latest.json` 按题数加权汇总六桶。

`export.json` 无法解析 → 仍记 `import_failure`（与「文件不存在」不同，避免把坏 JSON 当成「还没跑站外」）。

---

## 3. 题号怎么对齐

两边用**同一套**规范化，再当主键。

1. 全角数字 `０–９` 转半角；全角括号 `（）` 转 `()`。
2. 去掉空白；去掉行首「第」和「题」字。
3. 去掉末尾 `.` `．` `、`。
4. 若前面有「一、」「（一）」这类卷面大题前缀，只保留后面的阿拉伯数字题号。
5. 形如 `17(2)` 的保留为 `大题号(小问)`；`17` 与 `17(2)` **不是**同一题。

对齐顺序：

1. 规范化后的 `question_no` 相同 → 配成一对，标记 `aligned_by=question_no`。
2. 仍落单、且两边都有 `display_order` 的，按序号再配，标记 `aligned_by=order`（不可靠，报告单独列出）。
3. 只在一边出现、或一边把两题合成一题 / 拆成两题（同一题号重复）→ **只评切题**，不评答案等细项。

禁止按数组下标强行配对。

---

## 4. 卷面题号怎么从 Markdown 认出来

与全自动切块同一口径（`question_start_regex`）：

- 行首：`1.` `1、` `1．` `第 1 题`，后面跟空白或中文。
- 忽略考务行（「本试卷」「答题卡」「注意事项」等）。
- 大题号从 16 掉到 2 这类（且不是从 1 再起），视为小问误认成新大题，不记新题号。
- **编号从 1 再起**（选择 1–8 后填空又从 1 起），或行首「一、」「二、」大题头：新开一段。卷面题号键为 `{段}:{题号}`（如 `1:8`、`2:1`），同号多段不覆盖。

切题桶拿这组键去对 `full` / `export` 的题号（JSON 按 `display_order` 同样在「又从 1 起」时分段）。卷面有而该侧没有 → 该侧 fail；该侧有而卷面认不出 → 该侧 fail（多出）；同一键出现两次 → fail。

每道已对齐的题，用「本题号行 → 下一题号行之前」作为该题的 Markdown 切片，供答案、小问、题型判断。小问标记可以跟题号在同一行（例如 `19.已知……（1）……（2）`）。

---

## 5. 六个规则桶

每题每边、每个桶：`pass` / `fail` / `na`。没有加权总分，只看失败率和题级列表。

### 5.1 `cut` 切题

**通过：** 该侧题号集合与卷面可解析题号一致；没有漏题、没有把解析当新题、没有一题拆两题或两题并一题。

**失败常见原因：** 站外漏了后几题；全自动把「（2）」当成新的第 2 题；题号漂移对不上。

未对齐的题只进本桶，细项记 `na`。

### 5.2 `choice_schema` 选择题结构

适用：卷面切片是选择题选项表（行首连续 `A.`/`A、` 至少两行，或同行 `A. … B. … C.`）。「点 A」「集合 A」不算。否则若 JSON 已标 `choice` 仍评本桶。不是选择 → `na`。

**通过须同时满足：**

- `question_type` 为 `choice` 或 `multiple`。
- 选项在 `options` 里，标签为 A、B、C、D（或卷面实际项数）；不要缺项。
- 题干 `stem` 里不再残留 `A.` / `A、` 这类选项行。
- 卷面写「多选」或印刷答案有多个字母时，`sub_type` 应为 `multi`（`multiple` 也算过）。

### 5.3 `answer` 答案

先从该题 Markdown 切片抽印刷答案：

- `【答案】B`、`【答案】$\mathrm{B}$`
- `故选：B` / `故选 B`
- `[答案] BC`

抽不到印刷答案 → 本桶 `na`（不因此判错）。

**选择题：** JSON 的 `correct_answer.value.options` 规范化后（大写、去重、排序）须与印刷字母一致。空列表且卷面有答案 → fail。

**填空 / 解答：** 按小问标记 `（1）（2）` 把【答案】正文分段，与叶子 `answer` / 填空 `blanks` **规范化后全等**（LaTeX 空白、`\dfrac`/`\frac`、`\mathrm`）。禁止双向子串包含：叶子 `"1"` 不能对上 `（1）1（2）2`。完全对不上才 fail。

### 5.4 `parts` 解答题树

适用：卷面切片在【答案】之前出现至少两个小问标记 `（1）（2）` / `(1)(2)`（可与题干同一行），且不是选择题。否则 `na`。

**通过须同时满足：**

- `question_type` 为 `solution`。若 JSON 已标成 `fill`（填空带小问），本桶 `na`，不按解答题树扣分。
- 整题 `stem` 只放总前提；小问正文在 `parts`，不要整段 `(1)…(2)…` 留在 `stem`。
- `parts` 非空；叶子上有 `analyses` 或 `answer`。
- 整题 `analysis` 必须为空数组（解法写在对应叶子的 `analyses`）。

### 5.5 `editorial` 教辅杂质

看解析正文（选择题/填空的 `analysis[].content` 与 `title`；解答题叶子 `analyses`）。

**失败（有任一即可）：**

- 正文里仍有 `【分析】` `【点睛】` `【详解】` `【解析】` `【答案】` 标签。
- 条目 `title` 是「分析」「点睛」「详解」（「解法一」「解析」可以通过）。
- 短思路摘要：看**每条解析的第一行 / 首段**（按换行、空行或分号切开，与 `src/ai/slice/clean.rs` 一致）。含「即可得 / 即可求 / 即可判断 / 可求」等，或「根据……即可」，且该段较短、不像已展开的演算。

口径与 `src/ai/slice/clean.rs` 一致：【分析】【点睛】要去掉；【详解】可以留演算，但不能把标签本身留在 JSON 里。

### 5.6 `schema` JSON 契约

**通过须同时满足：**

- `question_type` 为 `choice` / `fill` / `solution` / `multiple` 之一。
- `correct_answer` 不是 null，且同时有 `kind` 与 `value`（选择题 `kind=choice` 且 `value.options` 为数组）。
- 公式分隔符只用 `$...$` / `$$...$$`，正文中没有 `\(` `\)` `\[` `\]`。
- 图片仍是 Markdown `![...](url)`，没有 `<img`。

## 6. 失败之后改哪里

脚本只出分流建议，**不自动改文件**。

| 对照（相对 Markdown） | 默认动作 |
|------------------------|----------|
| 站外该桶 pass、全自动 fail | 该题切片进 `src/ai/slice` 夹具，先写测试再改脚本 |
| 全自动 pass、站外 fail | 记站外未遵守提示词；多卷重复再考虑加提示词硬约束 |
| 两边同一桶都 fail | 先看 Markdown 是否 OCR 错（`ocr_error`）；卷面对则才允许改 `rules-prompts.md` |
| 未对齐 | 只修切题，不比较答案 |
| `import_failure` | 重出 JSON / 修转义，不算全自动回归失败 |

同一题两边各自错在不同桶：拆开两条，不要平均成「都差不多」。

---

## 7. 报告里有什么

- 对齐统计：按题号配上、按序号配上、仅全自动、仅站外。
- 各桶失败率：全自动、站外、两边同失败。
- 分流计数与题级明细（题号、桶、摘录）。
- 附录：`meta.json` 里的 skip / `llm_n`（若有），不计入结构对错。

报告写在试卷目录：`report.json`、`report.md`。扫整个 `bench/eval/` 时还有总清单 `bench/eval/report_latest.json`。

---

## 8. 怎么跑

在仓库根目录：

```text
python scripts/bench_eval_quality.py
python scripts/bench_eval_quality.py --dir bench/eval/某试卷名
python scripts/bench_eval_quality.py --self-check
```

脚本只读 `paper.md` / `full.json` / `export.json`，写出 `report.json` / `report.md`。不改 `src/ai/slice`、不改 `docs/rules-prompts.md`。

保真分（是否改写原文）不在本脚本内。交给站外模型时，用 `docs/全自动解析质量评估_裁判沟通词.md` 里的开场词 + 逐题词。
