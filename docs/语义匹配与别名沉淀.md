# 语义匹配与别名沉淀

> 状态：第 1 阶段已落地（`tagging-v3` 召回降噪 + 收敛映射）。第 2 阶段向量召回见 [语义匹配第2阶段_向量召回开发计划](语义匹配第2阶段_向量召回开发计划.md)（引擎 `tagging-v4`）。
> 关联：`docs/智能打标签统一改造.md`、`docs/requirements.md` §4.4。

## 1. 问题

编辑页「AI 智能打标」后出现两类失败，根因不是树上没有对应节点，而是**字面召回 + 名字数组收敛**无法表达「这个关键词等于那个已有节点」。

| 现象 | 根因 |
|------|------|
| 「集合」落在未匹配，树上已有「第一章 集合与常用逻辑用语」 | 短词对长教材名 trigram 过低；候选未进第二轮 |
| 「集合的交集运算」未对齐「交集的概念及运算」 | 汉字不完全相同；即使召回了，收敛只输出名字数组 |
| 树上勾了错误分支（如「函数与导数」） | 2 字泛化词根「运算」把无关节点拉进候选 |
| 树上已勾对，未匹配仍在 | 节点按 ID 去重只保留一个 `source_key`；消解未匹配靠字符串碰运气 |

系统**没有** embedding / pgvector。确定性通道是 `knowledge_nodes.aliases`（召回分 0.95），审核接口已有 `action=alias`，但确认保存写入 `tag_candidates` 时**不填** `suggested_node_id`，审核员只能新建节点。

## 2. 原则

1. **ID 必须在候选集内**：LLM 不得发明节点；`name` 必须与候选原名逐字一致。
2. **包含/分词不得升 exact**：短词「集合」不能自动打上所有含「集合」的节点。
3. **关键词 → 节点**是一等公民：收敛输出映射，而不是名字列表。
4. **复发术语走别名**：fuzzy 对齐成功或用户点「等于已有」，确认保存后进审核；通过即写入 aliases。之后不再进 LLM。
5. **候选只在确认保存后落库**（与统一打标一致）。

## 3. 第 1 阶段（本文执行）

### 3.1 召回降噪

`src/ai/tagging/repository.rs`：

- 分词仍按「的 / 与 / 及 / 和」切开。
- **不再**取 4 字以上片段的**尾双字**（「交集运算」不再抽出「运算」）。
- 头双字仍保留（「交集运算」→「交集」），但命中**泛化停用词**则丢弃：运算、概念、应用、基本、问题、方法、性质、及其、常用、用语、知识、专题、题型、内容、关系。
- 同一节点被多个关键词召回时，**合并 `source_keys`**，分数取高，不丢来源。
- 章节召回完成后，用章节关键词 + 已确定章节名对知识点/专题候选做路径加分（名称或 `name_path` 含主题词则 +0.12，上限 1.0），再按分数截断。

### 3.2 收敛协议（前后端共用 JSON）

LLM 输出（新）：

```json
{
  "chapter": [{"key": "集合", "name": "第一章 集合与常用逻辑用语"}],
  "knowledge": [{"key": "集合的交集运算", "name": "交集的概念及运算"}],
  "pattern": []
}
```

- `key`：阶段一提取的关键词（必须能对上未匹配项 `raw_name`）。
- `name`：候选列表中的**完整原名**；无合适项则 `null` 或省略，该 key 留在未匹配。
- 每个 key 最多对齐 1 个节点；每维最终采纳仍受上限 3 约束。
- 兼容：若模型仍返回旧字段 `chapter_names` / `knowledge_names` / `pattern_names`，按名字在候选中查找，并消解该候选的全部 `source_keys`。

引擎采纳一条映射后：

1. 将该候选写入 `matches`（`ai_name` = 该 key）。
2. 从未匹配中移除：该 `key`、候选全部 `source_keys`、候选原名。
3. 若该条为 **fuzzy**（非 exact/alias），生成 `alias_proposals[]` 写入建议 JSON，供排查；**确认保存不再自动进审核队列**（避免 10 题冒出上百条待审）。别名沉淀只走教师在未匹配上点的「等于已有」。

### 3.3 确认保存协议（前后端必须一致）

`POST /questions` 与 `PATCH /questions/:id` 的 `ai_tagging_confirmation`：

```ts
{
  suggestion_id: string
  unmatched_ids?: string[]          // 勾选「提交为新标签」的 unmatched.id
  alias_maps?: Array<{              // 「等于已有节点/标签」
    unmatched_id: string
    node_id?: string | null         // knowledge_node
    tag_id?: string | null          // method / core_competence
  }>
}
```

规则：

| 用户操作 | 请求 | 服务端 |
|----------|------|--------|
| 不勾选、不映射 | 两数组都不含该 id | 不写候选 |
| 勾选提交为新 | `unmatched_ids` 含 id | `tag_candidates` 无 suggested_* |
| 等于已有 | `alias_maps` 含 id + node_id 或 tag_id | 写候选且填 `suggested_node_id` / `suggested_tag_id`；**不再**当 new_node |
| 同一 id 同时出现 | `alias_maps` 优先 | 只走别名候选 |

另：建议里的 `alias_proposals`（fuzzy 自动对齐）**不再**在确认保存时写入 `tag_candidates`，以免每题 fuzzy 词都进审核。别名只走教师「等于已有」。待审核队列对 `(normalized_name, kind)` 全局去重。

`PendingCandidate` 增加 `suggested_node_id`、`suggested_tag_id`；`insert_confirmed_candidates` 写入这两列。

旧前端只传 `unmatched_ids` 时，`alias_maps` 缺省 `[]`。OCR 保存未带 confirmation 时只应用树上的匹配，不把 unmatched 整批入库。

### 3.4 编辑页

未匹配每一行：

- 复选框：提交为新标签（写入 `unmatched_ids`）。
- 「等于已有」：节点维用 `KnowledgeTreeCascader`（`max=1`，kind 与维度一致：chapter / knowledge / ability）；方法/素养用对应标签下拉。
- 映射成功后：取消「提交为新」；把该节点勾进对应树（章节/知识点/题型专题），或把标签勾进 `tagIds`，使本题真正挂上已有体系。

保存时 `buildPayload` 同时带 `unmatched_ids` 与 `alias_maps`。

### 3.5 审核页

列表/详情若 `suggested_node_id` 或 `suggested_tag_id` 非空，展示「建议别名」徽标。点「加为已有别名」时预填目标。通过后走现有 `append_node_alias` / 标签别名，下一题 exact/alias 直接命中。

## 4. 第 2 阶段（向量召回）

原则摘要（实施细节见 [语义匹配第2阶段_向量召回开发计划](语义匹配第2阶段_向量召回开发计划.md)）：

- DashScope `text-embedding-v3`（1024 维，`QWEN_API_KEY`）+ `pgvector`。
- 嵌入文本 = `name_path + 名称 + 别名`。
- 召回 = 字面 top-k ∪ 向量 top-k；向量命中一律 fuzzy，交给 3.2 收敛。
- 不塞进 `AiProvider`；单独 embedding 客户端。
- `CREATE EXTENSION vector` 无超管权限时迁移优雅跳过。
- 不自动把向量/fuzzy 命中写入审核队列。

用于覆盖「交集」↔「两个集合的公共元素」这类零字面重叠。第 1 阶段的别名闭环仍是复发术语的主路径。

## 5. 回归用例

- 「集合」fuzzy 召回「第一章 …集合…」类教材章节名，不得升 exact。
- 「集合的交集运算」fuzzy 召回叶子「…交集的概念及运算」，知识点不得召回非叶子。
- 分词不得产生停用词「运算」；集合题不得因「运算」召回「函数与导数」子树（集成环境用隔离树名）。
- 两关键词召回同一节点时，收敛映射一条 key 必须清掉两条未匹配。
- 幻觉名字仍丢弃。
- 确认保存：`alias_maps` 写入 `suggested_node_id`；仅 `unmatched_ids` 不写 suggested。
- 前端 `vue-tsc -b && vite build`。

## 6. 引擎版本

`ENGINE_VERSION = tagging-v4`（第 2 阶段向量召回并入候选集）。第 1 阶段召回词根与收敛 JSON 仍有效。
