# 题目内容模型与解析溯源

> 对照外部草案（Desktop `report.md`）与现网 `questions` / `ai_parse_tasks` / `documents` 字段后的**权威决策**。实现以本文为准；`docs/requirements.md` 中题型/答案示意已过期。
>
> **版本**：v1.0 · 2026-08-28

配套：[`全自动解析质量评估_闭环可行性.md`](全自动解析质量评估_闭环可行性.md)（评测 dump / gold，不改题目表）。

---

## 1. 职责边界（现网）

| 职责 | 现网位置 |
|------|----------|
| 解答题多问、多解 | `structure = {version, parts[]}`；分支只含局部 `stem`；叶子含 `answer` / `analyses[]` / `no_analysis_needed`。该题型 `analysis` 与 `correct_answer` 为 JSON null |
| 选择/填空解析 | `analysis TEXT`；多解约定用 `\n\n---\n\n` 拼接。本轮**不改列类型** |
| 答案规范 | `{kind, value}`：选择 → `value.options`；填空 → `value.blanks`。多选是 `question_type=multiple`，**`kind` 仍为 `choice`** |
| 业务态 vs 解析态 vs 内容缺口 | `questions.status`（draft/pending/rejected/published/disabled）/ `ai_parse_tasks.status` / `metadata.system_flags`（`pending_answer` / `missing_analysis` / `no_analysis_needed`） |
| 资料溯源 | `documents` → `papers.document_id` 或 `question_collections.document_id` → `paper_questions` / `collection_questions`。OCR 全文在 `ai_parse_tasks.progress.ocr_markdown` |
| 题目到解析任务 | `metadata.parse = {task_id, staged_index, saved_at}`（无新列）。任务 GC 后指针允许悬空 |
| 编辑版本 vs 解析版本 | `questions.version` + `question_versions.snapshot` 是人工编辑快照。pipeline / prompt / MinerU 版本只在任务或评测 `meta.json` |
| `parent_id` / `sub_order` | 遗留「复合题多行」。解答题禁止再用 `parent_id` 拆小问；小问只进 `structure` |

难度为整数 **1–5**（不是 easy/medium/hard）。题目属于 `space_id`。打标走 `ai_tagging_suggestions` / `ai_tagging_tasks`，与解析任务分离。

---

## 2. 答案 JSON（入站兼容、出站规范）

落库与 API 出站一律：

```json
{"kind":"choice","value":{"options":["A"]}}
{"kind":"choice","value":{"options":["A","C"]}}
{"kind":"fill","value":{"blanks":[{"position":1,"answer":"..."}]}}
```

解答题：`correct_answer` 为 JSON `null`，叶子答案只在 `structure.parts[].answer`。

入站仍接受裸 `["A"]`、`"A"`、`[{position, answer}]`、缺 `kind` 的对象；create/update 规范化后再写。空 `[]` / 空 `options` / 空 `blanks` 视为无答案，打 `system_flags.pending_answer`。

**禁止**：用 `type` 替代 `kind`；多选写成 `"kind":"multiple"`；解答题顶层再写一份 `summary`。

---

## 3. 明确不加的列与表

不加：`parse_status`、`parse_confidence`、`parse_metadata`、`processing_metadata`、`source_document_id`、`raw_content`。

不把 `analysis` 改成解答题 JSONB；不把 `structure` 改成 `{nodes:[]}`。

不新建 `parse_jobs` / `parse_attempts` / `parse_feedback`。任务表已是 `ai_parse_tasks`。错误样本与 gold 走评测文件，**不能用已保存 `questions` 当 after**（人工编辑和打标会污染结构）。

不迁移 `choice` / `multiple` 枚举名。解析 JSON 可用 `sub_type=multi`。

置信度、切块偏移、prompt hash **不**抄到题目行（人工一改即过期）。切块范围若存在，留在 `progress.staged_questions[]`，题目靠 `staged_index` 反查。

---

## 4. 选择/填空 `analysis TEXT`

仅服务选择与填空。多解用 `\n\n---\n\n` 分隔（前端拆成多段编辑）。若以后要结构化多解，只动这两类，且不得与解答题 `parts[].analyses` 再双写。

---

## 5. 与评测闭环的边界

`parse_attempts` / `parse_feedback` 对应 dump / `gold.json`，不是生产表。题目表不存 gold。dump 保留 `paper.md`、`full.json`、切块、`meta`（引擎、prompt hash、`task_id`）。规则分脚本 P0 见闭环可行性文档，本文不改评测脚本。

---

## 6. 对照外部 `report.md`

| 草案建议 | 判定 |
|----------|------|
| `analysis` 改 JSONB 承载多问多解 | 过时。解答题已在 `structure`；选择/填空保持 TEXT |
| `structure` 升级为 `{nodes:[]}` 内容树 | schema 写错。现网是 `{version, parts[]}`，不要换名、不要扩到选择/填空 |
| `correct_answer` 用 `{type, value}` | key 名错误。用已有 `kind` + 嵌套 `value` |
| 解答题 `correct_answer.summary` | 拒绝。会与叶子答案双写 |
| 题目上加 `raw_content` / 每题存 Markdown | 拒绝。全文在任务 `ocr_markdown` |
| `questions.source_document_id` | 拒绝。一题可挂多卷；走文档 → 试卷/集合 → 关联表 |
| `parse_status` 列 | 拒绝。解析态在任务表；内容缺口在 `system_flags` |
| `parse_confidence` 列 | 拒绝。只在暂存 `ParsedQuestion`；落库会过期 |
| `parse_version` / `processing_metadata` 列 | 拒绝。与 `question_versions` 不是一回事 |
| 重命名 `choice`→`single_choice` | 不迁移 |
| `parent_id` vs `structure` 二选一（未决） | 已决：解答题只用 `structure` |
| 新增 `parse_jobs` | 已是 `ai_parse_tasks` |
| 新增 `parse_attempts` / `parse_feedback` | 评测文件，不是新表 |

Desktop `report.md` 不在本仓库；本文生效后视为过期草案。
