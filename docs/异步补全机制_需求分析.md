## 一、用户故事

> **作为**一名高中数学老师，
> **我希望**在拿到最新模拟卷但官方答案尚未发布时，能先将题目题干录入系统保存为草稿，
> **以便**等答案公布后再补全答案与解析，最后批量提交审核。

**典型场景**：
1. 周一拿到联考卷 → 录入 20 道题干（无答案）→ 保存为草稿
2. 周二官方答案发布 → 进入「待补全」列表，逐个补全答案+解析
3. 补全后批量提交审核 → 进入正常审核流程

**AI 降级场景**：
1. AI 智能录入解析超时 / 公式提取失败 → answer 自动存为 null
2. 题目保存为草稿 + `⚠️ 待补全答案` 系统标签
3. 老师后续在「待补全」列表中手动补全

## 二、功能需求

### FR-1：草稿保存免校验答案

| 项 | 说明 |
|---|---|
| **触发** | 用户点击「保存草稿」 |
| **行为** | 不校验 `correct_answer` 和 `analysis` 是否为空 |
| **数据** | `correct_answer` 允许为 `null` 或空结构（`{"kind":"choice","value":{"options":[]}}`） |
| **状态** | 题目保持 `Draft` |

### FR-2：提交审核强制校验（答案 + 解析 + 选项）

| 项 | 说明 |
|---|---|
| **触发** | 用户点击「提交审核」 |
| **答案校验** | `correct_answer` 非空且非空结构；text/math 类型需 `.trim().is_empty()` 检测纯空格 |
| **解析校验** | `analysis` 非空且 `trim()` 后非空（除非 `no_analysis_needed=true`） |
| **选项校验** | 选择题（MCQ）必须校验 `options` 非空，防止"答案选 A 但选项内容为空"的脏数据 |
| **失败** | 返回 422 + 明细错误（缺哪些字段） |
| **成功** | 正常流转 `Draft → Pending` |

### FR-3：系统自动标签

| 项 | 说明 |
|---|---|
| **触发** | 题目保存/更新时，后端自动检测答案与解析是否为空 |
| **行为** | 在 `metadata.system_flags` 中写入/移除标志 |
| **标签** | `⚠️ 待补全答案`（`correct_answer` 为空时）、`⚠️ 缺解析`（`analysis` 为空时） |
| **自动消除** | 用户补全对应字段后，后端自动移除标签 |
| **可见性** | 前端列表卡片显示系统标签徽章 |

### FR-4：列表「待补全」筛选 + GIN 索引

| 项 | 说明 |
|---|---|
| **位置** | 题目列表页 header 栏，与「全部 / 已发布 / 草稿 / 待审核」并列 |
| **标签** | 「待补全」 |
| **筛选逻辑** | 显示 `metadata.system_flags` 包含 `pending_answer=true` 或 `missing_analysis=true` 的题目 |
| **排序** | 默认按创建时间倒序（最新录入的在前） |
| **计数** | Tab 上显示待补全题目数量 |
| **性能保障** | **GIN 索引必做**（`CREATE INDEX CONCURRENTLY ON questions USING GIN (metadata->'system_flags')`），避免全表扫描 |

### FR-5：批量提交审核 + 结果反馈 Modal

| 项 | 说明 |
|---|---|
| **触发** | 用户在「待补全」列表中选中多题后点击「批量提交审核」 |
| **行为** | 逐题校验答案完整性 + 选项完整性，全部通过才提交 |
| **部分成功** | 单题独立事务，已提交的不回滚 |
| **结果反馈** | **专用 Modal**（非 Toast），逐题列出成功/失败 |
| **失败明细** | Modal 中明确列出"题号 4、7、12 缺少答案提交失败"，并提供一键跳转锚点 |

### FR-6：无需解析 Override（开放题豁免）

| 项 | 说明 |
|---|---|
| **场景** | 开放性题目（如"请写出一个满足...的函数"）可能"无固定解析"或"答案见解析" |
| **UI** | 编辑页右侧属性面板新增「无需解析」Checkbox |
| **行为** | 勾选后 `metadata.system_flags.no_analysis_needed = true` |
| **效果** | 即使 `analysis` 为空，保存时也不写入 `missing_analysis: true`；`submit_for_review` 时豁免解析校验 |
| **取消** | 取消勾选后恢复自动检测 |

### FR-7：AI 解析异常自动降级

| 项 | 说明 |
|---|---|
| **触发** | AI 解析 Worker 遇到超时、公式提取乱码被丢弃等异常 |
| **行为** | 将 `correct_answer` 存为 `null`（而非丢弃整题），自动触发 `pending_answer` 标签 |
| **stem 兜底** | 如果 AI 连题干 `stem` 都未提取出（全黑/乱码图片），自动填入占位符 `[AI提取题干失败，请老师人工补充]`，避免违反 `NOT NULL` 约束导致 500 错丢弃整条记录 |
| **效果** | 题目保存为草稿，进入「待补全」列表等待人工补全 |
| **定位** | 作为 AI 解析异常的天然降级兜底，替代直接报错丢弃 |

### FR-8：批量提交结果反馈 Modal（专用交互）

| 项 | 说明 |
|---|---|
| **形式** | 专用 Modal 对话框（非 Toast 闪现） |
| **内容** | 总数 / 成功数 / 失败数；失败题目列表（题号 + 失败原因） |
| **操作** | 失败项提供「跳转编辑」按钮 |
| **跳转方式** | **必须新标签页打开（`target="_blank"`）或右侧抽屉（Drawer）弹出**，绝不能破坏当前列表页和 Modal 状态。老师改完一道题返回时，剩余失败题号仍在 Modal 中可见 |
| **关闭** | 关闭 Modal 后列表自动刷新，已提交的题目移出「待补全」 |

## 三、非功能需求

| 编号 | 需求 |
|---|---|
| NFR-1 | `system_flags` 检测逻辑延迟 < 5ms（内存计算，不额外查库） |
| NFR-2 | **GIN 索引必做**：`metadata->'system_flags'` 查询必须使用 `@>` 包含操作符命中 GIN 索引（`->>` 退化为 Seq Scan），分页不超过 200ms |
| NFR-3 | 向后兼容：存量题目（有答案）不受影响 |
| NFR-4 | 前端空答案渲染不崩溃（显示「答案待补全」占位） |
| NFR-5 | GIN 索引使用 `CONCURRENTLY` 创建，不锁表，不影响线上写入 |

## 四、数据模型

### 4.1 DDL 变更（仅 GIN 索引）

```sql
-- 阶段一必做：system_flags JSONB 深层查询索引
CREATE INDEX CONCURRENTLY IF NOT EXISTS idx_questions_system_flags
  ON questions USING GIN (metadata->'system_flags');
```

### 4.2 metadata 结构扩展

```jsonc
// metadata JSONB 现有结构 + 新增 system_flags
{
  "academic_year": "2026",
  "exam_region": "浙江",
  "paper_name": "2026届高三模拟考",
  // ── 新增 ──
  "system_flags": {
    "pending_answer": true,      // correct_answer 为空时自动设为 true
    "missing_analysis": true,    // analysis 为空时自动设为 true
    "no_analysis_needed": false  // 用户勾选"无需解析"时为 true，豁免 missing_analysis
  }
}
```

### 4.3 correct_answer 空值约定

| 场景 | JSON 值 | system_flags.pending_answer |
|---|---|---|
| 有答案 | `{"kind":"choice","value":{"options":["A"]}}` | `false` |
| 无答案（null） | `null` | `true` |
| 空结构 | `{"kind":"choice","value":{"options":[]}}` | `true` |
| 纯空格文本 | `{"kind":"text","value":"   "}` | `true`（trim 后为空） |

**空值判定逻辑**：
- `None` / `Value::Null` → 空
- `options` / `blanks` / `subs` 数组为空 → 空
- `value` 字符串 `trim()` 后为空 → 空（覆盖 text/math 纯空格）

## 五、API 变更

### 5.1 修改：`POST /api/v1/questions`（创建题目）

- `correct_answer` 字段改为可接受 `null`
- 后端自动检测并写入 `metadata.system_flags`
- 支持 `metadata.system_flags.no_analysis_needed` 字段

### 5.2 修改：`PUT /api/v1/questions/:id`（更新题目）

- 更新后重新检测并刷新 `metadata.system_flags`
- 支持更新 `no_analysis_needed` 字段

### 5.3 修改：`POST /api/v1/questions/:id/submit`（提交审核）

- 新增答案完整性校验（非空 + 非空结构 + 非纯空格）
- 新增选择题 `options` 非空校验
- 新增解析非空校验（`no_analysis_needed=true` 时豁免）
- 校验失败返回 422 + 错误明细

### 5.4 新增：`GET /api/v1/questions?status=draft&system_flag=pending_answer`

- 支持按 `system_flag` 筛选（走 GIN 索引）

### 5.5 新增：`POST /api/v1/questions/batch-submit`（批量提交审核）

- 接收 `{question_ids: [uuid]}`
- 逐题校验 + 批量流转（单题独立事务）
- 返回成功/失败明细列表

### 5.6 新增：`GET /api/v1/questions/incomplete-count`（待补全计数）

- 返回 `{"pending_answer": 5, "missing_analysis": 3, "total_incomplete": 7}`
- 供前端 Tab 计数和 Dashboard 统计

## 七、验收标准

| 编号 | 验收标准 |
|---|---|
| AC-01 | 创建题目时 `correct_answer` 为 `null` 可成功保存为草稿 |
| AC-02 | 草稿题目自动显示「⚠️ 待补全答案」系统标签 |
| AC-03 | 补全答案后系统标签自动消失 |
| AC-04 | 提交审核时如果 `correct_answer` 为空，返回 422 错误 |
| AC-05 | 提交审核时如果 `analysis` 为空且 `no_analysis_needed=false`，返回 422 错误 |
| AC-06 | 提交审核时如果 `analysis` 为空但 `no_analysis_needed=true`，校验通过 |
| AC-07 | 提交审核时选择题 `options` 为空，返回 422 错误 |
| AC-08 | `correct_answer` 为纯空格字符串（`{"kind":"text","value":"   "}`）被判定为空 |
| AC-09 | 题目列表页「待补全」Tab 正确筛选出缺答案/缺解析的题目 |
| AC-10 | 「待补全」Tab 显示待补全题目数量 |
| AC-11 | 存量已发布题目不受影响（无系统标签显示） |
| AC-12 | 前端空答案渲染显示「答案待补全」占位，不崩溃 |
| AC-13 | AI 解析失败时题目自动保存为草稿 + `pending_answer` 标签 |
| AC-14 | AI 连 stem 都未提取时，自动填入占位符 `[AI提取题干失败，请老师人工补充]`，题目仍落库不丢 |
| AC-15 | 批量提交 20 题中 3 题失败时，Modal 列出失败题号 + 原因 + 跳转编辑 |
| AC-16 | 「跳转编辑」在新标签页或抽屉中打开，不破坏列表页和 Modal 状态 |
| AC-17 | 「无需解析」Checkbox 勾选后 `missing_analysis` 标签不出现 |
| AC-18 | GIN 索引已创建，`EXPLAIN ANALYZE` 确认 `@>` 查询走 Bitmap Index Scan（非 Seq Scan） |
