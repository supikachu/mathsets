# 智能打标签统一改造

> 状态：第 1–7 阶段已落地（契约、Engine、编辑页确认保存、Worker 暂存、候选治理分支、异步打标任务、测试/观测/影子比对与死代码清理）。

## 录题入库时机（已确认）

AI OCR / 结构化完成后**不会**写入 `questions` 表。Worker 只把解析结果写入 `ai_parse_tasks.progress.staged_questions`（含预计算匹配、hash 去重标记）。用户在编辑工作台点保存，`POST /questions` 携带 `ai_meta` 后才真正建题、写关联、写候选。未保存的暂存项由 GC 清理。

统一改造保持这一确认点：**建议可在解析时生成，题目和候选只在用户确认保存后落库。**

## 五维契约

| 维度 | 落点 | 约束 |
|------|------|------|
| `chapter` | `knowledge_nodes`（tree.kind=chapter） | 允许父节点 |
| `knowledge` | `knowledge_nodes`（tree.kind=knowledge） | 仅活动叶子 |
| `pattern` | `knowledge_nodes`（tree.kind=ability） | 仅活动叶子 |
| `method` | `tags.category=method` | 不进专题树 |
| `core_competence` | `tags.category=core_competence` | 封闭词表 |

引擎版本：`tagging-v4`。召回与别名沉淀见 [语义匹配与别名沉淀](语义匹配与别名沉淀.md)。exact=1.0 / alias=0.95；包含、分词词根与向量命中进入 **fuzzy**（向量分封顶 0.80）。收敛输出关键词→候选原名；fuzzy 对齐在确认保存后进入别名候选。收敛失败不再静默 Top1。

数量上限（服务端强制）：章节 3、知识点 3、题型专题 3、通用方法 5、核心素养 3。
