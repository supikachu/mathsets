# 异步补全机制 — 可行性报告

> 生成日期：2026-08-09
> 状态：评审通过（v2 — 已纳入评审反馈）
> 变更摘要：GIN 索引升级为必做；新增 AI Worker 降级、无需解析 Override、批量结果 Modal

---

## 一、需求背景

现实教学中，老师拿到最新联考卷/模拟卷时，官方答案往往晚半天甚至第二天才出。当前系统要求题目保存时必须填写 `correct_answer`，严重阻碍最新题目录入效率。

**目标**：允许老师先保存「无答案草稿」，后续再异步补全答案与解析，最后批量提交审核。同时作为 AI 解析异常的天然降级兜底。

## 三、差距分析

| 维度 | 现状 | 目标 | 差距 |
|---|---|---|---|
| 草稿保存 | `correct_answer` 必填（API 层） | 允许空答案保存 | `correct_answer` 需改为 `Option<serde_json::Value>` |
| 提交审核校验 | **无**答案完整性校验 | 提交时强制校验答案+解析+选项 | `submit_for_review` 需新增校验逻辑 |
| 系统标签 | 无自动标签 | 缺答案/缺解析自动打标 | 需新增系统标签机制 |
| 列表筛选 | 4 个 Tab | 新增「待补全」Tab | 前端+后端新增筛选维度 |
| 状态锁定 | 无约束 | 无答案题目锁定在 Draft | 提交审核时拦截 |
| AI 解析异常 | 报错丢弃 | 自动降级为待补全草稿 | AI Worker 错误映射 |
| 开放题无解析 | 强制补解析 | 支持"无需解析" Override | 新增 `no_analysis_needed` 标志 |
| JSONB 查询性能 | 无索引 | GIN 索引保障 | 新建 migration（**必做**） |

## 四、可行性评估

### 4.1 技术可行性 — ✅ 可行

| 改动项 | 难度 | 风险 | 说明 |
|---|---|---|---|
| `correct_answer` 改为 `Option` | 低 | 低 | DB 层已为 nullable（`serde_json::Value` 可存 null），仅需调整 Rust 类型 |
| `submit_for_review` 新增校验 | 低 | 低 | 在现有状态校验后追加答案完整性 + 选项完整性检查 |
| 系统标签机制 | 中 | 中 | 可复用 `metadata` JSONB 字段存储 `system_flags`，无需新表 |
| 前端「待补全」Tab | 低 | 低 | 在现有 `statusTabs` 数组追加一项 |
| 后端「待补全」筛选 + GIN 索引 | 中 | 低 | **必做**：JSONB 深层字段查询需 GIN 索引，否则全表扫描 |
| AI Worker 异常降级 | 低 | 低 | 解析失败时 answer 存 null，自动触发 `pending_answer` 标签 |
| "无需解析" Override | 低 | 低 | `metadata.system_flags.no_analysis_needed` 布尔标志 |
| 批量提交结果 Modal | 中 | 低 | 前端设计明细 Modal，逐题列出成功/失败 |

### 4.2 数据兼容性 — ✅ 安全

- `correct_answer` 字段在数据库中已是 `JSONB`（支持 null）
- 存量数据不受影响：已有题目都有非空 `correct_answer`
- 新增 `system_flags` 存入 `metadata` JSONB，无需 DDL 列迁移
- GIN 索引 `CREATE INDEX CONCURRENTLY` 不锁表，不影响线上写入

### 4.3 风险分析

| 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|
| AI 录题输出空答案后用户遗忘补全 | 中 | 中 | Dashboard 显示「待补全」计数提醒 |
| `correct_answer` 为空导致前端渲染崩溃 | 低 | 高 | 前端增加空答案容错渲染 |
| 批量提交审核时部分题目缺答案 | 中 | 低 | 后端返回明细错误 + 前端结果 Modal 逐题列出 |
| JSONB 深层查询全表扫描 | 高 | 高 | **GIN 索引必做** + **`@>` 包含操作符**（`->>` 退化为 Seq Scan） |
| 开放题被误判为"缺解析" | 低 | 低 | `no_analysis_needed` Override 豁免校验 |

## 五、结论

**推荐方案**：采用「`metadata.system_flags` 软标签 + `submit_for_review` 校验门 + GIN 索引保障 + AI 异常降级」方案。

**核心理由**：
1. **零列迁移** — `correct_answer` 已是 JSONB nullable，`system_flags` 存入 `metadata`，仅需 GIN 索引 migration
2. **GIN 索引必做** — 保障 JSONB 深层字段筛选性能，`CREATE INDEX CONCURRENTLY` 不锁表
3. **AI 天然降级** — AI 解析失败 → null answer → 自动触发 `pending_answer` 标签，无需额外错误处理
4. **开放题豁免** — `no_analysis_needed` Override 覆盖"答案见解析"等特殊场景
5. **渐进式上线** — 阶段一（后端+索引）→ 阶段二（校验门）→ 阶段三（前端）
