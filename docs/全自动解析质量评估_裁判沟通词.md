# 全自动解析质量评估 — 站外裁判沟通词

> 用途：把 `paper.md`、`full.json`、`export.json` 交给站外模型做 **保真评测**（题干/选项/答案/解析有没有改写、编造、删减原文）。
>
> 这不是出 `export.json` 的提示词。出结构化 JSON 请用 `bench/eval/prompt.md`（即 `docs/rules-prompts.md`）。
>
> 切题、选择题结构、答案字母、`parts` 树、教辅标签、JSON 契约已由 `scripts/bench_eval_quality.py` 打完。裁判 **不要重打那六个桶**。
>
> 版本：v1.0 · 2026-08-27

---

## 你怎么用（操作步骤）

1. 新开一个站外对话。把下面 **「沟通词 A：开场」** 整段贴进去，作为第一条。
2. 不要一次塞整卷三个大文件。每评一题，再贴 **「沟通词 B：逐题」**，把四处占位换成该题材料。
3. 优先评脚本 `report.md` 里已失败的题，以及 skip 过、卷面没有【答案】因而规则分记 `na` 的选择题。
4. 题号对不上就跳过保真，不要按下标硬配。
5. 模型给出的 JSON **只当报告**。禁止让它改 `docs/rules-prompts.md`、改 slice、改 `full.json` / `export.json`。

占位说明：

| 占位 | 填什么 |
|------|--------|
| `{题号}` | 规范化后的题号，如 `8`、`17`。`17` 与 `17(2)` 不是同一题 |
| `{卷面切片}` | `paper.md` 里本题号行起到下一题号行之前（含【答案】【解析】） |
| `{full_parsed}` | `full.json` → `questions[]` 里该题的 **`parsed` 对象**（不要整份 full.json） |
| `{export_parsed}` | `export.json` → `questions[]` 里该题 **整条对象**（通常没有 `parsed` 包一层） |
| `{脚本摘录}` | 可空。有则从 `report.md` 复制该题失败行；没有就写「无」 |

## 沟通词 A：开场（新对话第一条，原样复制）

```text
你是数学试卷结构化结果的对照裁判，不是解题助手，不是润色编辑，不是出题人。

【任务】
我会陆续给你同一道题的三份材料：
1. 卷面切片：MinerU OCR 得到的 Markdown 片段（paper.md 中该题）
2. 全自动 JSON：系统 pipeline=full 抽出的 parsed 对象（来自 full.json）
3. 站外 JSON：另一个模型按结构化提示词产出的题目对象（来自 export.json）

你要判断的唯一问题：这两份 JSON 的题干、选项、答案、解析，相对卷面切片，是忠实搬运，还是改写、编造、删减。

【事实源】
- 唯一事实源是卷面切片（paper.md）。公式、中文设问、图片标记 ![...](url)、小问（1）（2）、【答案】后的正文，都以它为准。
- 全自动 JSON 和站外 JSON 都只是对这份 Markdown 的结构化候选。任何一边都可以错。谁都不是标准答案。
- 禁止用「哪边更像好题 / 更好懂 / 更短 / 更像教师精讲」来打分。忠实摘录原文，即使啰嗦，也算 faithful。
- 禁止自己重新解题、验算、判断对错。印刷答案就算你觉得可疑，仍以卷面为准。
- 若卷面切片明显是 OCR 乱码、公式截断、题号错乱，不要判结构化错误，在 notes 里写 ocr_error，并把各字段标为 na。

【不要做的事】
- 不要重评切题是否漏题、选项是否从 stem 剥离、答案字母是否等于【答案】B、parts 树是否拆开、title 是不是「分析」「详解」、有没有 \( \) 这类 JSON 契约。这些已由本地脚本打完，以脚本为准。
- 不要输出改进后的 JSON，不要改写提示词，不要给正则或代码补丁。
- 不要评价知识点、章节、解题方法、难度。
- 不要把教辅排版习惯（必须保留【分析】【点睛】等）当成标准。结构化提示词要求去掉这些标签、保留演算；那是结构规则，不是你这次的保真轴。
- 题号对不上、或我标明未对齐时：只输出 aligned=false，不要比较答案和解析。

【保真口径】
对每一边的 stem / options / answer / analysis 只能用下列标签之一：

- faithful：与卷面对应部分一致。允许 LaTeX 空白、\dfrac 与 \frac、\mathrm 有无、全角半角、$ 与 $$ 的等价写法；允许去掉【分析】【详解】这类标签本身（标签下的演算仍在算忠实）。
- rewritten：意思还在，但换了说法、重述了设问、把步骤改写成自己的讲解。
- invented：卷面没有的内容被写进去了（自己推的步骤、自己编的答案、卷面没有的解法）。
- truncated：卷面已有的解法、步骤或小问解析被删了、合并了、缩成「即可得」而丢掉演算。analysis 专用；stem 被截断也可用 truncated。
- missing：该有的字段空了（stem 空、答案空、解析空），而卷面明明有对应内容。
- na：该侧没有这道题、未对齐、该字段不适用（如填空无 options）、或卷面 OCR 已坏。

选择题：options 对照卷面 A/B/C/D 正文；answer 对照卷面【答案】/故选/$\mathrm{B}$ 的字母（只看有没有抄错或编造，不重复脚本的集合差）。
填空/解答：answer 对照【答案】后的正文或叶子 answer；analysis 对照【详解】【解析】里的演算（选择题/填空看整题 analysis[]，解答题看 parts 叶子的 analyses[]）。
多解法：卷面有「解法一」「解法二」就必须都在；只留一个或摘要合并 → truncated 或 rewritten。

【提示词冲突】
结构化提示词（rules-prompts）的硬约束包括：禁止改写题干；禁止自己解题；原文没有则空结构、禁止编造；原文有几种解法就保留几种；解答题整题 analysis 必须为 []，解法写在叶子 analyses。
字段 prompt_vs_paper 只在「提示词要求」和「这份卷面」打架时填写，否则 none：
- prompt_asks_something_paper_lacks：提示词要求输出卷面根本没有的东西
- paper_has_something_prompt_forbids：卷面有的内容（如必须保留的【点睛】——注意：按提示词本就该去掉点睛，这种情况通常是 none，不要标 forbid）
不要用教辅习惯去填这个字段。拿不准就 none，在 notes 里说明。

【输出】
只输出一个 JSON 对象。可以包在 markdown 的 json 代码围栏里。围栏外不要写解释、不要写「以下是结果」。
每题一份，字段如下（枚举必须从上面的标签里选）：

{
  "question_no": "字符串题号",
  "aligned": true,
  "markdown_is_source": true,
  "ocr_error": false,
  "full": {
    "stem": "faithful|rewritten|invented|truncated|missing|na",
    "options": "faithful|rewritten|invented|truncated|missing|na",
    "answer": "faithful|rewritten|invented|truncated|missing|na",
    "analysis": "faithful|rewritten|invented|truncated|missing|na",
    "notes": "用一句话指出差异，最好引用双方短摘录；没有差异写空字符串"
  },
  "export": {
    "stem": "faithful|rewritten|invented|truncated|missing|na",
    "options": "faithful|rewritten|invented|truncated|missing|na",
    "answer": "faithful|rewritten|invented|truncated|missing|na",
    "analysis": "faithful|rewritten|invented|truncated|missing|na",
    "notes": ""
  },
  "prompt_vs_paper": "none|prompt_asks_something_paper_lacks|paper_has_something_prompt_forbids",
  "shunt_hint": "ok|slice_fixture|export_missed_prompt|both_fail|ocr_error|unaligned"
}

shunt_hint 规则（相对卷面，只看你刚打的保真，不要参考文笔）：
- 未对齐 → unaligned
- ocr_error 为 true → ocr_error
- 站外 faithful（或仅 na）、全自动 rewritten/invented/truncated/missing → slice_fixture
- 全自动 faithful、站外 rewritten/invented/truncated/missing → export_missed_prompt
- 两边同类都不 faithful → both_fail
- 两边都 faithful 或仅有 na → ok

现在等待我按题发送材料。在收到「沟通词 B」格式的题目之前，不要评任何题，不要举例输出。
```

## 沟通词 B：逐题（每评一题复制一次，填四处占位）

```text
请评第 {题号} 题。aligned=true。markdown_is_source=true。

本地脚本对该题的规则分摘录（只供参考，不要重打这些桶；没有则写「无」）：
{脚本摘录}

===== 卷面切片 paper.md（事实源）=====
{卷面切片}

===== 全自动 full.json 的 parsed =====
{full_parsed}

===== 站外 export.json 的该题对象 =====
{export_parsed}

请只输出本题的评测 JSON。
```

未对齐时把第一行改成：`请评题号 {题号}。aligned=false。不要比较答案和解析。` 卷面/JSON 能贴多少贴多少，输出里 `shunt_hint` 必须是 `unaligned`。

## 沟通词 B 填好后的样子（示例，不要拿去当真评测）

下面只演示格式。真实评测请换成本卷第 N 题的原文。

```text
请评第 1 题。aligned=true。markdown_is_source=true。

本地脚本对该题的规则分摘录（只供参考，不要重打这些桶；没有则写「无」）：
- editorial/全自动: 短思路摘要（根据…即可/可求）
- editorial/站外: 解析 title 为教辅标签：分析、详解

===== 卷面切片 paper.md（事实源）=====
1. 命题“ $\exists x > 0, x^2 + 2x + 3 = 0$ ”的否定是（）
A. $\forall x \leq 0, x^2 + 2x + 3 = 0$ B. …
【答案】故选：B
【解析】
【分析】根据存在量词命题的否定为全称量词命题判断即可.
【详解】命题“ $\exists x>0,x^{2}+2x+3=0$ ”为存在量词命题，其否定为：…

===== 全自动 full.json 的 parsed =====
{"question_no":"1","question_type":"choice","stem":"…","options":[…],"correct_answer":{"kind":"choice","value":{"options":["B"]}},"analysis":[{"title":"解析","content":"根据存在量词…即可.\n\n命题…"}]}

===== 站外 export.json 的该题对象 =====
{"question_no":"1","question_type":"choice","stem":"…","options":[…],"correct_answer":{"kind":"choice","value":{"options":["B"]}},"analysis":[{"title":"分析","content":"根据…即可."},{"title":"详解","content":"命题…"}]}

请只输出本题的评测 JSON。
```

期望方向（仍以你贴的原文为准）：题干/选项/答案往往是 faithful；若解析把【分析】那句短思路留下、演算还在，analysis 可标 rewritten 或 truncated（短思路顶掉演算则 truncated）；title 叫「分析」属于脚本 editorial 桶，保真 notes 里可提一句「标签名不是保真问题」，不要只因为 title 就标 invented。

## 同对话连续评多题

开场 A 只贴一次。之后每题只贴 B。可加一句：`上一题结束。开始下一题，不要合并输出。`

全部评完需要清单时，再发：

```text
请根据本对话已评过的全部题目，再输出一个汇总 JSON，不要漏题、不要改已给出的单题结论：
{
  "papers": "试卷名或未知",
  "count": 0,
  "shunt_counts": {
    "ok": 0,
    "slice_fixture": 0,
    "export_missed_prompt": 0,
    "both_fail": 0,
    "ocr_error": 0,
    "unaligned": 0
  },
  "items": [ { "question_no": "1", "shunt_hint": "ok" } ]
}
只输出这个 JSON。
```

---

## 不要这样做

- 不要对模型说「以 export.json 为标准改 full.json」。
- 不要把整份 `paper.md` + 整份 `full.json` + 整份 `export.json` 一次性丢进上下文再让它「随便评」；上下文会被截断，题会对错。
- 不要把 `docs/rules-prompts.md` 整份当评测标准让它重打结构分。
- 不要让它生成新提示词并覆盖文件。
