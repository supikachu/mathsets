# 全自动解析质量评估 — 闭环可行性与数据规范

> 本文把「错误样本库 → LLM 错因 → 算法/Prompt 建议 → 分层评测集」收成可落地规格。对照外部备忘（统一 Schema、错误库、16 类标签、候选区域检测、100/500/1000 评测集）与当前压测/规则分脚本。
>
> 配套：`docs/全自动解析质量评估_需求分析.md`（为何评、失败后改哪）、`docs/全自动解析质量评估_评测规则.md`（六桶语义）、`docs/全自动解析质量评估_裁判沟通词.md`（保真分人工沟通词）。
>
> **本文档版本**：v1.0 · 2026-08-28
>
> **约束**：本文是规格，不改 `src/ai/slice`、不改 `docs/rules-prompts.md`。实现须另开任务，并与本文逐条对照。裁判与建议脚本 **不得** 自动写回代码或提示词（需求分析 C6）。

## 1. 总判

方向对：**不要追求一套正则打遍所有高中资料**，应建设「标准 Schema + 高质量 Prompt + 轻量算法 + LLM 结构理解 + 可回归评测 + 错误样本库」。

现状能跑全自动 dump 与六桶规则分，但 **评测本身有 P0 缺陷**。在修完 §3 之前：

- `--reuse` 的 baseline/after **不能**当结构回归；
- 规则分失败率 **不能**直接拿去改正则或 Prompt；
- 错误样本库和 100 题冻结集 **不可复现**。

先修评测（文档级 OCR 缓存 + 规则分 P0），再冻 V0、再建错误库，最后才做 LLM 归因与建议草案。

三条必须改写外部备忘的前提：

1. **站外 JSON 不是 gold。** 库内已保存题也不能当 `after`（编辑和打标会污染结构）。唯一结构 gold 是人工确认的 `gold.json`。
2. **两条链路并不共享同一份 Prompt。** 全自动 Stage2 走 `STAGE2_PATCH_PROMPT`（通常只喂题干 + 规则草稿）；站外走 `docs/rules-prompts.md`（整卷 Markdown）。`CORE_PARSE_RULES` 与站外提示词有测试对齐，但运行时 PATCH 是第三份文本。
3. **评测集按题计，不按「份资料」。** 第一期已有约 10 卷 / 206 题，盖过 100 题门槛。「100 份资料」会把 OCR 配额与人工 gold 放大一个数量级。

## 2. 外部备忘条款 vs 当前脚本

源：`scripts/bench_full_auto_parse.py`、`scripts/bench_eval_quality.py`、`docs/全自动解析质量评估_*.md`、`src/workers/ai_parse_worker.rs`。

| 条款 | 现状 | 判定 | 卡点 |
|------|------|------|------|
| 同一 OCR 上对照全自动 / 站外 | dump 能落 `paper.md`；`--reuse` 仍新建任务并重跑 MinerU | 文案与实现相反 | 缓存键在 `task.progress.ocr_markdown`，不在 document |
| 规则分 + 失败分流 | 六桶 `pass/fail/na`；`slice_fixture` / `export_missed_prompt` / `both_fail` | 能跑，但会系统性误判 | 答案子串包含、选择题过检、题号 dict 覆盖；缺 `export.json` 则整卷作废 |
| 错误样本库 before/after | 只有 `full.json`，没有 `gold.json`，没有切块原文 | 缺关键输入 | 不能用 `questions` 表当 after；暂存 72h GC |
| LLM 错误归因 + 16 类标签 | 裁判沟通词已写，脚本明确不调 LLM | 规格有、实现无 | 公式/编造/语义丢失只能靠保真分 |
| 自动生成算法 / Prompt 建议 | 禁止裁判改文件（C6） | 只能出草案 | 聚类「删除该规则」候选，禁止生成 if-elif 补丁 |
| 统一题目结构化规范 | `CORE_PARSE_RULES` 与 `rules-prompts.md` 有测试对齐 | 半套 | 运行时全自动走 PATCH，与站外 FULL 不是同一份 |
| 100 / 500 / 1000 评测集 | 第一期锁定 10 卷约 206 题；`bench/eval/*` gitignore | 修完 P0 后规模可达成 | 按题计；冻结 `bench/evalset/`，不要用 inbox 临时 dump |

速度压测（`bench/out/`）与质量评测（`bench/eval/`）是两条线：`--compare` 只看 ms/题和 skip，不看六桶。

## 3. 规则分 P0（必须先修）

脚本能出 `report.md`，但下列误判会改分流方向：把错的打成对、把解答题打成选择、把 OCR 漂移当成 slice 回归。

| ID | 问题 | 后果 | 应先改 |
|----|------|------|--------|
| P0-1 | `--reuse` 新建任务；OCR 缓存在 task，不在 document | after 相对 baseline 可能是 MinerU 漂移；日配额翻倍 | 文档级 `ocr_markdown` 缓存；或评测只 `--dump-from` 已有 task |
| P0-2 | `slice_paper` 用 dict；选择 1–8 后再从 1 起的填空会覆盖或丢题 | cut / answer 对照的不是同一题切片 | 卷面题号改成 `(大题前缀, 题号)` 或允许多段编号 |
| P0-3 | 填空/解答答案规范化后双向子串包含 | 叶子只要写出「1」就能对上「（1）1（2）2」；answer 失败率被压低 | 按小问对齐后精确/规范化全等，禁止 `gold ⊂ cand` |
| P0-4 | `paper_is_choice` 见到「点 A」「集合 A」就算选择 | 解答题被按 choice 打；parts 被标 `na`；`both_fail` 会去改提示词 | 只认选项表（行首 `A. B. C. D.`），不要搜正文里的 `A.` |
| P0-5 | 重跑 dump 覆盖 `paper.md`/`full.json`，不碰已有 `export.json` | 新 OCR + 旧站外 JSON 被当成一次对照 | `paper.md` sha 变化则作废同目录 export，或换目录 |
| P0-6 | 缺 `export.json` 整卷 `import_failure`，六个桶都不打 | 站外滞后时全自动单边回归为零；`main()` 遇一单失败就 exit 1 | 允许只评 full 相对 `paper.md`；跨卷加权汇总 |

补充（P1，规模化前应修，不阻塞 V0 冻结准备）：

- 评测切题是字符串题号，运行时可能走 MinerU bbox / `rehome_trailing_exam_sections`，题号集合会偏。没有 `chunks.jsonl` 时须标记 `slice_source=eval_reparse`。
- `fail` vs `na` 仍记分流；分流计数是每题每桶一条，不是每题一条。
- 站外 JSON 评测用严格 `json.loads`，产品导入会剥围栏、修非法 LaTeX 转义；分段多个 `{questions:[...]}` 无法自动拼接。
- `meta.prompt.sha256` 锁的是 `rules-prompts.md`，不是运行时 `STAGE2_PATCH_PROMPT`。
- `extract_full_questions` 无 `skip_or_llm`、不过滤 `merged_into`。
- inbox 不递归、无锁定文件列表；多放一份 PDF 就 silently 换样本。

`bench/inbox/PUT_PDFS_HERE.txt` 写「不再上传、跳过 OCR」与 `--reuse` 实现相反。修 P0-1 之前，结构对照只用：

```text
python scripts/bench_full_auto_parse.py --dump-from bench/out/<label>_latest.json
python scripts/bench_eval_quality.py
```

## 4. 必须留存的原始数据

现在能复现的只有「同一份 OCR Markdown → 最终 staged JSON」。归因还需要：这一题怎么被切、是否跳过 LLM、模型当时看到和返回了什么。

### 4.1 优先级

| 优先级 | 产物 | 现在 | 用途 |
|--------|------|------|------|
| P0 必须 | `paper.md` + `markdown_sha256` + 真实 `ocr_engine` | 有 markdown；引擎被脚本写死 mineru；`--reuse` 会覆盖成新 OCR | 共享事实源；sha 变了必须作废同目录 export |
| P0 必须 | `chunks.jsonl`：每块 `source_md` / `split_via` / bbox span | 仅内存与 tracing | 区分 MinerU 粘段、规则切错、评测再切不一致 |
| P0 必须 | `gold.json`（人工确认后的 `ParsedQuestion[]`） | 不存在 | 唯一结构 gold；禁止用 export 或库内题代替 |
| P1 应该 | `script_draft`：`confidence` / `reasons` / `skip_llm` | 混在 `parsed.warnings` 字符串里 | 判断 High 跳过是否切错，还是 polish 洗过了头 |
| P1 应该 | `prompt_id` + sha256 + model（PATCH vs FULL vs 站外） | meta 只锁 `rules-prompts.md` | 避免把两套提示词当成公平对照 |
| P2 抽样 | LLM raw JSON、导入 raw、`content_list` 原始 | 用完即扔 | 复现截断 / invalid escape / 版面 bbox 精度 |
| 不要当主对象 | `questions` 表、知识点打标、耗时 token | 保存后可编辑；token 列 n/a | 污染结构；附录指标，不进对错 |

### 4.2 运行时缺口（worker / API）

- GET `/ai/parse-task/{id}` 已返回 `ocr_markdown`、`slice_timing`、`staged_questions`；`ocr_engine`、`ocr_layout_path` 写在 progress JSONB 但响应未映射。
- `slice_timing.chunk_count` 实际是合并后题数 `merged.len()`，不是切块数。
- 私有部署 MinerU 往往只留 Markdown，无 zip / content_list，`split_via` 常为 `markdown_fallback`。
- 逐页降级路径默认不写全文 `ocr_markdown`（`ocr_export` 除外）。

### 4.3 目录约定

两套目录分开，不要混用：

```text
bench/eval/                 # 当轮 dump，gitignore（现状）
  <试卷名>/paper.md
  <试卷名>/full.json
  <试卷名>/export.json
  <试卷名>/gold.json        # 待补
  <试卷名>/chunks.jsonl     # 待补
  <试卷名>/meta.json
  <试卷名>/report.json
  prompt.md
  manifest.json

bench/evalset/v1/           # 冻结评测集，可入库（脱敏后）
  manifest.json             # 版本号、试卷清单、题量、分层、prompt hash
  papers/<paper_id>/
    paper.md
    gold.json
    strata.json             # 资料类型：普通卷 / 解析卷 / 练习 / …
```

PDF、账号、`bench/out/` 运行结果仍不进 git。`src/ai/slice` 测试夹具继续放代码旁，由错误库 **生成候选**，人工确认后入库。

## 5. 错误样本 JSON（`error_sample.v1`）

外部备忘的 `source / before / after / errors[]` 太粗。一题一条样本，必须能回答：错在哪一层、相对谁错、默认改哪里。

### 5.1 设计约束

- `before`：全自动 `parsed`（可附 `path`）。
- `after`：只允许 `gold` 或人工确认后的修正，**不允许**站外 JSON。
- `export`：可选对照，不是 gold。
- `errors[]` 用 §5.3 的 16 类标签；每条必须带 `tag`、`stage`、`shunt`、`evidence`。没有摘录的标签视为无效。
- 运行时切块缺失时 `chunk_md` 可空，并标记 `slice_source=eval_reparse`。
- 分流沿用需求分析 §7：站外对、全自动错 → `slice_fixture`；反过来 → `export_missed_prompt`；两边同错先查 OCR，再才允许动 `rules-prompts.md`。

### 5.2 Schema

```json
{
  "schema_version": "error_sample.v1",
  "paper_id": "hangzhou-yizhong-2024",
  "question_no": "18",
  "document_id": "uuid",
  "task_id": "uuid",
  "ocr": {
    "engine": "mineru",
    "markdown_sha256": "…",
    "layout_source": "mineru"
  },
  "prompts": {
    "stage2_patch_sha256": "…",
    "rules_prompts_sha256": "…",
    "text_model": "…"
  },
  "slice": {
    "split_via": "mineru",
    "slice_source": "runtime_chunk",
    "chunk_index": 17,
    "chunk_md": "18. 已知……\n【分析】……"
  },
  "before": {
    "path": "script_skip",
    "parsed": {}
  },
  "export": {
    "model": "外部模型名",
    "parsed": {}
  },
  "after": {
    "source": "gold",
    "parsed": {}
  },
  "rule_score": {
    "cut": { "full": "fail", "export": "pass" },
    "answer": { "full": "na", "export": "na" }
  },
  "errors": [
    {
      "tag": "analysis_mapping_error",
      "rule_bucket": "cut",
      "stage": "cut",

```

字段枚举：

| 字段 | 允许值 |
|------|--------|
| `slice.split_via` | `mineru` / `doc2x_pages` / `markdown_fallback` |
| `slice.slice_source` | `runtime_chunk` / `eval_reparse` |
| `before.path` | `script_skip` / `llm_merge` / `llm_fallback_ocr` |
| `after.source` | `gold` / `human_edit` |
| `errors[].stage` | `ocr` / `cut` / `skip` / `llm` / `polish` / `import` |
| `errors[].shunt` | `ok` / `slice_fixture` / `export_missed_prompt` / `both_fail` / `ocr_error` / `unaligned` / `import_failure` |

一卷可另写 `errors/<paper_id>.jsonl`（一行一题），与题级文件二选一即可，schema 相同。

## 6. LLM 怎么分析错误，建议怎么出

三层模型，**顺序不能反**。规则分是回归真值；LLM 归因是解释层；优化建议是聚合层。任何一层都不得写回 `src/ai/slice` 或 `docs/rules-prompts.md`。

```text
同一 OCR → dump（paper / full / export）→ 人工 gold
        → L0 规则分 → L1 错因 → L2 建议草案
        → 人工确认 → 独立任务改算法或 Prompt → reuse 同一 OCR 重跑结构化
```

| 层 | 输入 | 输出 | 禁止 |
|----|------|------|------|
| L0 规则分（先修 P0） | `paper.md` + `full.json`；`export` 可缺 | 六桶 + shunt + 题级 reasons；无 export 时只评 full | 调 LLM；按数组下标对齐；把 `fail` vs `na` 当成对称分流 |
| L1 错因（待做） | 卷面切片 + 两边 parsed + 脚本摘录 + 可选 `chunk_md` | `tags[]` + `stage` + `evidence` + `shunt_hint` | 重打六桶；输出改进 JSON；用「更好懂」当错 |
| L2 建议（待做） | ≥1 个冻结评测集上的标签直方图 + 命中规则名 | 删除/降权候选、Prompt 条文 diff、夹具清单 | 生成 if-elif 补丁；无 `both_fail` 证据时改提示词 |

L1 复用 `docs/全自动解析质量评估_裁判沟通词.md` 的口径（`markdown_is_source`、保真标签、`shunt_hint`），并多输出 §5.3 的 `tag`。优先评规则分已失败的题，以及 skip 过、印刷答案抽不到因而 `na` 的题。不要一次塞整卷三个大文件。

### 6.1 算法建议只允许三类

1. **删除或降权**一条现有规则，并给出该规则在冻结集上的失败率（例如「发现【答案】立即结束题目」失败率 23% → 建议删除）。
2. **把硬切片改成候选跨度**：算法只标「可能是题 / 答案区 / 解析区」，结构交给 LLM。这是产品架构变更，**不**在评测脚本里替换现网切题。
3. **失败题做成** `src/ai/slice` 夹具（先红后绿），而不是直接改 worker。

准入仍按需求分析 §7.1：至少一道来自本评估的失败题成为夹具；目标桶下降，其它桶失败题数不得增加 ≥ 2 或失败率升 ≥ 3 个百分点（须在报告中解释）。

### 6.2 Prompt 建议的准入

1. 至少一条两边相对 Markdown 同错，或站外系统性违反 **已有条文**。
2. 输出条文级 diff，拆成三层（不要把 PATCH 失败算到站外 FULL 头上）：
   - 任务定义
   - 结构规范（Schema）
   - 关键判定规则（硬约束）
3. 变更与 `CORE_PARSE_RULES` 的测试锁定同步。
4. **不**由裁判模型直接覆盖 `docs/rules-prompts.md`。

## 7. 100 / 500 / 1000 题评测集

单位统一为 **题**。资料只做分层来源。份数按高中卷均约 20 题估算。第一期口径见需求分析 §8.1（10 卷 / 约 206 题）。

| 版本 | 规模 | 大约资料份数 | 来源分层 | gold 做法 | 验收 |
|------|------|--------------|----------|-----------|------|
| V0 冻结 | 现有 ~206 题 | 10 | 当前解析卷原样锁定 | 失败桶每桶至少人工看 3 题；对齐失败整卷人工看 1 次 | 必须先修 P0-1～6，再用 `--dump-from` 锁 `paper.md` |
| V1-100 | 100 题子集 | ~5–8 | 普通卷 / 带解析 / 复杂解答 / 练习各一段 | 每题必须有 `gold.json`；skip 与 LLM 题按现网比例抽 | 约 5 次配额；改 slice 后其它桶不得 +2 题或 +3pp |
| V1-500 | 500 题 | ~25 | 补课堂练习、课后作业、专题 | 规则分全量；保真分分层抽 20% | 25 次配额；必须文档级 OCR 缓存 |
| V1-1000 | 1000 题 | ~50 | 再加 5–10 份双栏/跨页/粘题号教辅 | 未失败题可延用规则 pass 为弱 gold | 增删试卷必须升 `manifest` 版本号 |

日配额约 50 次/用户。V1-1000 首轮会打满配额；`--reuse` 在 P0-1 修好之前会再吃一轮 OCR。保真分 500 题以上必须抽样，不能靠人工逐题粘贴。

锁定清单要求（与需求分析 8.1 一致，本文指定路径）：

- 文件名 / `document_id` / 题量 / 分层 / prompt hash 写入 `bench/evalset/v1/manifest.json`。
- 评测默认使用冻结 Markdown，禁止无故重传 PDF、禁止 inbox 多放文件 silently 换样本。

## 8. 建议落地顺序

| 周次 | 做 | 不做 |
|------|----|------|
| 1 | 文档级 OCR 缓存让 `--reuse` 名副其实（或评测只用 `--dump-from`）；答案匹配去子串；选择题检测收紧；题号允许多段；无 export 可单边评分 + 跨卷加权 | 建错误库、改切片策略、让裁判改 Prompt |
| 2 | dump 补 `gold.json` / `chunks.jsonl` / `ocr_engine` / 双 prompt hash；冻结 V0；L1 归因脚本（复用裁判沟通词） | 用站外 JSON 当 gold；在未锁 `paper.md` 时跑 after |
| 3 | 从 shunt 生成 slice 夹具草案；L2 只输出「删除该规则」类建议 | 把候选区域检测直接替换现网切题 |
| 之后 | V1-100 作为每次算法/Prompt 变更的必跑回归；500/1000 按分层加卷 | 追求一份正则打遍所有高中资料 |

候选区域检测是架构变更，评测闭环只负责提供「硬切片失败率」证据，不在本规格内替换 `split_question_chunks`。

## 9. 成功标准

实现完成时应能回答：

1. 冻结集上，全自动相对 **gold / Markdown** 的切题、选项、答案、`parts`、教辅杂质各错多少？其中多少是 skip 独有、多少是 Stage2 独有？
2. 哪些失败带 `error_sample.v1` 与 `stage`，默认进 slice 夹具还是 Prompt 草案？
3. 改完一轮后，**同一份** `markdown_sha256` 上目标桶是否下降、有无回退？
4. L2 建议是否附失败率与题号清单，且未经人工确认没有改仓库文件？

若只能给出「哪边 JSON 更像」、或 `--reuse` 前后 `paper.md` hash 不一致，则评测实现不合格。
