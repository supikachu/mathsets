## 产品概述

将「导出」与「排版」拆分为两个独立模块：**导出引擎**（负责把试题篮题目导出为 Word / PDF / Markdown，Word 中公式为可编辑 OMML 原生公式）与**排版系统**（面向题库 / 教辅场景、具备 InDesign 级版面控制力、由代码与数据驱动的简易排版内核）。两模块解耦：Word / Markdown 不经过排版系统，PDF 由导出引擎经统一数据接口委托排版系统渲染。

教师在试题篮中选题组卷后，打开导出面板选择格式（Word / PDF / Markdown）、输出模式（学生练习 / 教师讲义 / 标准考卷）与版面参数（纸张、分栏、密封线、留白样式），实时预览分页效果并下载成品文件。Word 中公式可双击进入公式编辑器编辑；PDF 达到印刷级质量（字体全嵌入、纯黑 K100、A3 对折密封线卷）；公式解析失败时安全降级为红色原文并给出警告，**不中断整卷导出**。

## 一、已确认的技术决策

| 决策点 | 结论 |
| --- | --- |
| LaTeX → MathML | 本地 `latex2mathml` crate（纯 Rust，离线，替代 MathType 外部服务） |
| MathML → OMML | **Rust 等价实现 MML2OMML.XSL 转换规则**（不引入 libxslt 原生依赖）；微软官方 XSL 文件打包至 `assets/xsl/MML2OMML.XSL` 作为**规范基准 + 黄金快照测试对照源**，运行时不执行 |
| Typst 集成 | 进程内嵌入 `typst` / `typst-pdf` / `typst-svg` crate，无状态编译 |
| LaTeX → Typst math | `mitex` crate（Typst 社区转换器，覆盖矩阵/cases/嵌套上下标等，远优于手写宏映射） |
| 字体 | 思源宋体 SC + 思源黑体 SC（Regular/Bold，OFL 许可允许再分发）**提交入库** `assets/fonts/`；拉丁/数学字体用 `typst-assets` 内嵌 |
| 组卷结构 | 前端携带完整分组结构（大题标题 + 有序题目 + 分值），**导出结果与试题篮页面所见一致** |
| 交付范围 | 全量一次到位，按 5 个里程碑纵切分期提交 |

## 二、现状结论（代码库探索）

- 后端 Rust / Axum 0.8 + sqlx（`src/handlers/*` + `src/models/*`，`AuthUser` Extension 鉴权，错误统一 `(StatusCode, Json)`）；前端 Vue 3 + Vite + Tailwind + KaTeX。
- 题目内容格式：`stem` 为 Markdown 风格文本，内嵌 `$...$` / `$$...$$` LaTeX、`![alt](url){width,align}` 图片、`:::img-row` 图组围栏、Markdown 表格；解答题问树在 `structure` JSONB（`QuestionPart`）；选项/答案为 JSONB 规范形（`{kind,value{options/blanks}}`）。
- 试题篮**纯前端内存态**（`useQuestionBasket` 模块级 Set）；`Basket.vue` 已有题型分组（中文序号大题 + 连续题号）与选项解析回退（`parseOptions` / `extractOptionsFromStem`）；「下载试卷」仅为 `window.print()` 占位。
- 图片存 `{UPLOAD_DIR}/questions/`，`/uploads` 静态挂载；`zip = "2"`、`infer = "0.16"`、`image`（webp+png）已是依赖。
- **全库无任何导出/排版现存代码**（`src/ai/layout/` 是 OCR 版面识别，无关不复用）。
- 可复用：`models/question_structure.rs` 问树解析、`get_question` 的空间可见性判定（`can_access_space` + Public 空间仅 Published）。

## 三、总体架构：两个解耦模块 + 两层 IR

```mermaid
flowchart LR
  A[Basket.vue 组卷 JSON] --> B[POST /api/v1/export/*]
  B --> C[src/export 导出引擎<br/>装配+切分+OMML+DOCX+MD]
  C -->|ExamBundle + Options| D[export::pdf 适配器 唯一桥]
  D --> E[src/typeset 排版系统<br/>LayoutSpec→Block IR→Typst DSL→编译]
  E --> F[PDF / SVG 预览流 / 预检报告]
  C --> G[Markdown / DOCX 直出]
```

- **两层 IR**：`ExamBundle`（导出域：内容与语义）与 `LayoutDoc/LayoutBlock`（排版域：带 `breakable` / `keep_with_next` 元数据）。`export::pdf` 适配器把前者映射为后者，是**模块间唯一接口**；Word / Markdown 完全不经过排版系统，排版系统也可被其他来源（如已有 Paper 表）复用。
- Handler 遵循仓库惯例放 `src/handlers/export.rs` 与 `src/handlers/typeset.rs`；路由在 `src/lib.rs` 的 `build_app()` 函数内、名为 **`protected_routes` 的局部 `Router` 绑定**（非独立函数，见 `src/lib.rs:83`）上链式 `.route()` 注册，该 Router 整体经 `.nest("/api/v1", protected_routes)` 挂载（`src/lib.rs:369`）。
- `assets/xsl/MML2OMML.XSL`（规范基准，测试对照）与 `assets/fonts/`（思源宋体/黑体 SC，约 60MB）纳入版本管理，换取无外部依赖的确定性渲染；**字体经 git-lfs 管理**，落地配置见 §十三。

## 四、API 契约

```
POST /api/v1/export/markdown   → text/markdown；?bundle=true 时 zip（md + images/）
POST /api/v1/export/docx       → application/vnd.openxmlformats-officedocument...
POST /api/v1/export/pdf        → application/pdf（委托 typeset，按 mode 取默认 spec）
GET  /api/v1/typeset/profiles  → 版面预设列表
POST /api/v1/typeset/render    → PDF 字节流（完整 LayoutSpec 控制）
POST /api/v1/typeset/preview   → { pages: [svg...], page_count, issues, warnings }
```

**请求体 `ExamRequest`**（三格式共用；sections 由前端 `groupedSections` + `displayNoMap` 序列化，保留用户排序选择）：

```json
{
  "title": "…", "subtitle": "…",
  "exam_meta": { "school": "…", "duration": 120, "total_score": 150, "instructions": ["…"] },
  "mode": "student | teacher | exam",
  "sections": [{ "title": "一、单选题", "instruction": "…", "questions": [{ "id": "uuid", "default_score": 5 }] }],
  "options": {
    "include_answer": true, "include_analysis": false, "answer_at_end": true,
    "callouts": { "knowledge": true, "error_prone": true, "analysis": true },
    "answer_space": { "style": "lines | dots | blank", "height_cm": 6 }
  },
  "spec": { "paper": "a4 | a3_fold | a3_tri", "columns": 2, "sealing_line": true, "...": "…" }
}
```

- 响应带 `Content-Disposition: attachment; filename*=UTF-8''...`（RFC 5987 中文文件名）。
- **降级警告**：文件类响应经 `X-Export-Warnings` 头返回（URL-encoded JSON：`[{question_no, field, latex, reason}]`）；预览响应在 body 中返回 `issues`。
- 权限：`WHERE id = ANY($1)` 批量取题 → 复用 `get_question` 可见性判定（空间成员 / Public 空间仅 Published / 管理员），不可见题跳过并记入警告。

## 五、模块 A 详细设计：导出引擎 `src/export/`

### 5.1 ExamBundle（`model.rs`）与装配器（`assembler.rs`）

- `ExamBundle { title, subtitle, exam_meta, mode, sections: Vec<ExamSection> }`；`ExamSection { title, instruction, questions: Vec<ExamQuestion> }`。
- `ExamQuestion { number（后端按请求顺序重排的连续题号）, score, kind(SingleChoice|MultiChoice|Fill|Solution|Composite), stem: Vec<InlineNode>, options, answers, analyses, structure_parts(复用 QuestionPart), callouts, answer_space, issues }`。`score` 取自前端 `default_score` 字段（缺省时按后端默认值）；`Composite`（综合题）对应前端 `bucketType()` 的第 5 个题型桶，不可遗漏。
- 装配：批量查库 + 可见性过滤 → 选项解析（兼容裸字符串数组 / `{label,content}` / 题干内嵌 A-D 回退，移植 `Basket.vue` 逻辑）→ 解答题展开 `structure` 问树。
- **Callout 数据派生**（教师/讲义模式）：
  - 考点清单框 = `knowledge_nodes`（主知识点置顶）
  - 易错警示框 = `error_prone` 类标签
  - 名师点拨 = `analysis`
  - 思路拆解 = 问树 `analyses` 各解法块
  - 统一 `Callout{kind,title,nodes: Vec<InlineNode>}` 挂到题块。

### 5.2 内容切分器（`content.rs`）

对 `stem` / `analysis` / 选项 / 问树文本做一次性扫描，输出 `InlineNode` 序列，三种生成器共用：

- `Math{latex, display}`：`$$...$$`、`\[...\]`（块级）；`$...$`、`\(...\)`（行内）；`\$` 转义跳过。
- `Image{url,width,align}`：`![alt](url){width,align}` 语法（width/align 可选）。
- `ImgRow[...]`：`:::img-row` 围栏（内部图片 + 图注行）。
- `Table`：Markdown 管道表格。
- `Text` / `LineBreak`：其余文本。

### 5.3 LaTeX → OMML 管线（`math/omml.rs`，核心）

```
LaTeX 源串 --latex2mathml--> Presentation MathML 字符串
           --quick-xml--> MathML 节点树
           --MML2OMML.XSL 等价规则（Rust 递归下降转换器）--> OMML 节点树
           --quick-xml 写出--> <m:oMath> XML 片段
```

- **规范基准机制**：`assets/xsl/MML2OMML.XSL`（随 Office 分发的官方版本）入库，运行时不执行。角色：① 实现对照——每条 Rust 映射规则逐一对应 XSL 的 `xsl:template match="mml:..."`（含 `isNary` n-ary 运算符识别、`FStartOfRun` run 边界、`OutputText` 文本后处理等模板语义）；② 黄金快照源——开发期用外部 XSLT 引擎（Python lxml / xsltproc，仅开发机需要）执行官方 XSL 生成参考输出，存为 `tests/snapshots/*.omml` 固件，CI 断言 Rust 实现与快照**XML 规范化后逐节点一致**（忽略属性顺序与空白）。
- **元素映射表**（递归下降 `match` 节点名）：

| MathML | OMML | 备注 |
| --- | --- | --- |
| `math` | `m:oMath` | display 时外包 `m:oMathPara` |
| `mrow`/`mstyle`/`mpadded` | 透传子节点 | |
| `mi` | `m:r`（斜体，Cambria Math） | `mathvariant="normal"` → `m:sty val="p"` |
| `mn` / `mo` | `m:r` | `mo` 内容直接进 `m:t` |
| `mfrac` | `m:f`（`m:num`/`m:den`） | `linethickness="0"` → `m:fPr m:type="noBar"` |
| `msqrt` / `mroot` | `m:rad` | `msqrt` 空 `m:deg` |
| `msub`/`msup`/`msubsup` | `m:sSub`/`m:sSup`/`m:sSubSup` | |
| `munder`/`mover` | `m:limLow`/`m:limUpp` | 大型运算符（∑∫∏）→ `m:nary`（`naryPr chr` + `limLoc="undOvr"`）；带 accent 的 `mover` → `m:acc` |
| `munderover` | 大型运算符 → `m:nary`；否则拆分嵌套 | |
| `mtable`/`mtr`/`mtd` | `m:m`/`m:mr`/`m:e` | 矩阵 / 方程组（cases） |
| `mfenced` | `m:d` | open/close → `m:dPr` begChr/endChr |
| `menclose` | `m:borderBox` / `m:bar` | `\cancel` 等 |
| `mtext` / `mspace` | `m:r`（`m:sty="p"`）/ `m:t` 空格 | 中文文本块 |
| `mphantom` | `m:phant` | |
| `mathvariant` | `w:rPr/w:rFonts` 的 script/fraktur/double-struck | |
| 未知节点 | 递归子节点 + 记警告 | 容错降级，不 panic |

- run 属性：每个 `m:r` 内 `<w:rPr><w:rFonts w:ascii="Cambria Math" w:hAnsi="Cambria Math"/></w:rPr>`。
- 嵌入：行内 `m:oMath` 混排在 `w:p` 的 `w:r` 之间；块级独占 `w:p > m:oMathPara > m:oMath`。
- 容错：`latex2mathml` 或转换失败 → 该公式降级为红色 `w:r` 原文 + 记警告，**绝不让单题失败中断整卷**。

### 5.4 DOCX 包（`docx/`）

最小 OOXML 包（zip 复用 `zip = "2"`）：

- `[Content_Types].xml`：默认 rels/xml/png/jpeg 扩展 + document/styles/settings overrides。
- `word/document.xml`：首页大卷头（试卷名 + 考试说明 + 大题分值汇总表 + 学校/班级/姓名/考号信息表）→ 大题标题段（灰色底纹 `w:shd` + 分值统计）→ 小题段（悬挂缩进题号）→ 选项 → 按模式内嵌/卷末答案与解析（Callout 用底纹段落框）→ 末尾 `sectPr`（纸张、页边距、页脚 `第 X 页 共 Y 页` 域）。
- **防腰斩**：题干与选项段落链式 `w:keepNext` + `w:keepLines`；解答题按小问分块 keep。
- **选项智能布局**：复用排版系统 `blocks::choice_grid` 的确定性估宽决策（§6.2，同一算法单测覆盖），输出无边框 `w:tbl` 网格（1×4 / 2×2 / 4×1）。
- `word/styles.xml`：Normal（宋体 + Times New Roman，10.5pt）、大题标题、题号、选项、Callout 样式。
- `word/settings.xml`：`m:mathPr`（mathFont=Cambria Math，保证公式可编辑渲染）。
- `word/media/` + rels：图片按 `/uploads/questions/...` → `state.upload_dir` 本地路径读取，`infer` 嗅探格式，EMU 单位 `wp:inline` 内嵌，`{width,align}` 配置生效（上限 14cm）。
- **SVG 配图**：PNG/JPEG 直嵌；SVG 在 docx 中**跳过并记警告**（M5 用 resvg 位图化补齐）。
- **边界**：Word 竖排密封线（文本框旋转）在纯 XML 生成下不稳定 → DOCX 仅做装订边加宽 + 首页信息表；完整密封线为 PDF 路径能力。

### 5.5 Markdown 生成器（`markdown.rs`）

- 结构：YAML frontmatter（题名/模式/总分）→ `# 大题`（含题数分值统计）→ 题干 → 选项 → 按开关内嵌或卷末汇总答案/解析；Callout 用 `> [!NOTE]` 风格引用块。
- 公式 `$...$` / `$$...$$` **原样保留**（KaTeX/MathJax 可直接渲染）；文本段做最小转义（`*` `_` `` ` `` `#` 等），公式段不转义。
- `bundle=true`：返回 md + `images/` 的 zip（复用图片抓取逻辑）。

### 5.6 PDF 适配器（`pdf.rs`）

`ExamBundle + ExportOptions` → `typeset::ir::LayoutDoc` + `LayoutSpec`（mode → 默认 spec：student=A4 单栏、exam=A3 对折双栏等）→ `typeset::compile_pdf()`。

## 六、模块 B 详细设计：排版系统 `src/typeset/`

### 6.1 参数模型（`spec.rs`）

```rust
struct LayoutSpec {
    paper: Paper,                // A4 | A3Fold(8开对折) | A3Tri(三栏) ；宽高 mm + 双面标记
    columns: u8,                 // 1 | 2 | 3
    margins: Margins,            // 四边 + gutter 栏间距
    binding: Option<Binding>,    // 密封线：Left | CenterFold；校名/姓名/考号填涂区开关
    header_footer: HeaderFooter, // 动态页眉(当前大题名) / 第X页共Y页 / 奇偶外侧
    profile: OutputProfile,      // Student | Teacher | Exam
    fonts: FontSpec,             // 正文=思源宋体 / 标题=思源黑体 / 数学=New Computer Modern
    answer_blank: BlankSpec,     // 留白高度 / 横线格 / 点阵
    color: ColorMode,            // Rich | PrintBlackOnly(K100 纯黑)
}
```

内置预设：A4讲义单栏、A4练习双栏、A3对折双栏考卷、A3三栏考卷；`GET /typeset/profiles` 返回，前端参数化覆盖（结构化 JSON 模版注入）。

### 6.2 Block 引擎（`blocks/`）

- **IR**（`ir.rs`）：`LayoutDoc { title, meta, sections: [Section{header, blocks}] }`；`LayoutBlock` 枚举：`Question{no, stem, options: Option<ChoiceGrid>, figures, keep_together}` / `SubQuestion` / `Blank` / `Callout` / `AnswerKeyItem` 等，每种带 `breakable` / `keep_with_next` 元数据。
- **题型模板注册表**（`blocks/mod.rs`）：`QuestionKind -> Box<dyn BlockBuilder>` trait；新增题型（连线/证明）只注册新 builder，不触碰排版核心。
- **选项智能布局**（`choice_grid.rs`）：确定性估宽（CJK 1em、ASCII 0.55em、公式段按字符数 ×0.55em 加权）→ 决策表：
  - 所有选项 ≤ 可用栏宽 25% → **1 行 4 列**；
  - ≤ 50% → **2 行 2 列**；
  - 超长或含多行公式 → **4 行 1 列**。
  输出 `ChoiceGrid{columns,rows}` 供 typst `grid()` 与 docx `w:tbl` 共用——**同一算法、两处渲染、单测覆盖决策表**。
- **防跨页**：整题 `#block(breakable: false)`；解答题按小问分块，小问标题 `keep with next`（禁孤立页脚）。
- **左文右图**（`figure_float.rs`）：题干 `grid(columns: (1fr, 35%))` 绑定文字与图，图不失宽度。
- **答题留白**（`blank.rs`）：学生模式输出指定高度 + 横线格（`line(length: 100%, stroke: 0.5pt)` 循环）/ 点阵；教师版折叠为解析 Callout。

### 6.3 Typst DSL 生成（`typst_gen.rs`）

- 头部：`#set page(...)` / `#set text(font: ..., lang: "zh")`（行首禁则 + `cjk-latin-spacing` 盘古之白，Typst 内建）/ `#set par(justify: true, leading: ...)`。
- 布局函数库：`#let question-block(...)`、`#let section-header(...)`（灰底 + 分值框）、`#let choice-grid(...)`、`#let callout(...)`（考点/点拨/易错/思路四色框）、`#let answer-blank(...)`、`#let sealing-line(...)`（rotate 90° 虚线 + 垂直「密封装订线，请勿折叠」+ 填涂区）。
- **A3 对折**：A3 横向 `columns(2)`，每栏宽 = A4 版心宽，内容左栏→右栏自然流动；中线画折线 + 密封线。三栏卷同理 `columns(3)`。
- **母版分离**：首页大卷头（试卷名 + 考试说明 + 大题分值汇总表 + 信息填涂区），后续页常规版心（`page(...)` 首页参数分离）。
- **页眉页脚**：页眉 `context` 提取当前大题名；页脚 `第 X 页（共 Y 页）`；`odd_even_outer=true` 时奇偶页码外侧对齐。
- **公式**：`mitex` crate 把 LaTeX 转 Typst math 内嵌源码（基线自动对齐）；mitex 失败再降级红色原文等宽块 + 记 issue。
- **公式编号**：块级公式输出 `(大题.序号)`，号由 Rust 侧在生成时数（R10）；交叉引用仅对带 label 的源文本生效（数据现状无 label 语法，正文全量编号），卷末答案区不属任何大题故不编号。

### 6.4 编译器（`compiler.rs`）

- 实现 `typst::World`：虚拟 `main.typ` 源（生成的 DSL）、字体集（`typst-assets` 内嵌 + `assets/fonts/` 思源宋体/黑体）、`/uploads/**` → `upload_dir` 文件映射、`today()` 等。
- `compile_pdf(spec, doc) -> Vec<u8>`：`typst::compile` → `typst_pdf::pdf`（默认全字体内嵌）；`compile_svg_pages(...) -> Vec<String>`：`typst_svg::svg` 逐页（供毫秒级预览）。
- 性能：每请求独立 World 保持无状态；`comemo` 增量缓存命中重复编译（预览场景），外加请求级 LRU（请求体 hash → 产物）兜底——目标单卷 ≤500ms、百页 ≤2s，基准测试验证。（**这一句两处已作废**：LRU 由 R13 实测改判为「comemo 就是那一层，缺的只是容量上界 `comemo::evict`」；两个常数按同一轮的裁决重述为「≤80 页 ≤2s + 百页走热请求、混合卷 500ms 降为回归哨兵」。）
- `PrintBlackOnly`：全文 `luma(0%)` 纯黑（K100，防四色黑重影）。

### 6.5 印前预检（`preflight.rs`）

- 位图有效 DPI：`image` crate（补 jpeg/gif feature）读像素尺寸 ÷ 版面显示宽 → <300 记警告并建议换 SVG；SVG 直嵌不检。
- 溢流检测：收集 typst 编译诊断（warning/error），逐题定位。
- 字体缺失 / 公式降级 / 图片跳过统一汇总 `Vec<Issue>`，随预览 JSON 返回前端展示。

## 十一、风险与边界

- 思源宋体 / 黑体 SC 为 OFL 许可，允许随二进制分发（成立）；仓库体积增加约 60MB，**已确定采用 git-lfs**（落地配置见 §十三）。两个必须提前防范的坑：① LFS 规则须**先于首次字体提交**，否则二进制进入 git 历史后需 `filter-branch` / BFG 重写历史才能迁出；② 未安装 git-lfs 的克隆者只会拿到 132 字节 pointer 文件，导致中文豆腐块且极难排查，由 `scripts/check_fonts.{ps1,sh,bat}` 主动拦截。
- `latex2mathml` 长尾宏覆盖不全 → 降级原文 + 警告，后续按需扩展；mitex 同理，但 PDF 路径优先 mitex、Word 路径（OMML）不受 mitex 影响。
- Rust 等价实现与官方 MML2OMML.XSL 可能存在边角偏差（如 run 切分粒度）：黄金快照覆盖核心用例拦截回归，未覆盖的罕见构造以 Word 实际打开验证为准，偏差项按需补齐规则。
- Word 竖排密封线在纯 XML 生成下不稳定 → DOCX 简化为装订边加宽 + 首页信息表，完整密封线为 PDF 能力。
- 公式交叉引用仅对带 label 的源文本生效（题目数据现状无 label 语法），编号本身全量生效。
- typst crate API 版本间变动较大 → 锁定版本，`compiler.rs` 按所选版本文档实现 `World`。
- SVG 配图：docx M1-M4 跳过并告警，M5 resvg 位图化补齐；PDF 路径 typst 原生支持 SVG 直嵌。
- 试题篮不持久化不影响导出（请求自带全量 ID + 顺序）。

## 十二、仓库实施惯例（后端）

本节为实施时必须遵循的既有代码约定，均已核实。

### 12.1 目录与路由注册

- Handler 一律放 `src/handlers/`，新增模块需在 `src/handlers/mod.rs` 追加一行 `pub mod xxx;`（现有 20 个模块，均为逐行 `pub mod`）。
- 路由在 `src/lib.rs` 的 `build_app()` 函数内、名为 **`protected_routes` 的局部 `Router` 绑定**（`src/lib.rs:83`，非独立函数）上链式 `.route()` 注册；受保护分组内部**不使用 `nest`**，约 130 条路由全部平铺。
- 该 Router 整体经 `.nest("/api/v1", protected_routes)` 挂载（`src/lib.rs:369`）。**易错点**：`/api/v1` 前缀只加在受保护路由上；公开路由（`/health`、`/api/v1/auth/login`、`/api/v1/auth/register`、`/api/v1/notifications/stream`）自行书写完整路径。
- 需要放大 body 上限的路由用 `.merge()` 单独套 `DefaultBodyLimit`：`/users/avatar` 2MB、`/uploads/images` 10MB（`src/lib.rs:162-172`）、`/ai/documents` 80MB（`src/lib.rs:328-332`）。导出请求体仅含题目 ID 列表与版面参数，量级很小，沿用默认上限即可。

### 12.2 鉴权

- `AuthUser` 定义于 `src/auth/middleware.rs:23-29`，字段为 `id` / `username` / `role` / `global_role`。
- 由 `require_auth` middleware 注入（`req.extensions_mut().insert(auth_user)`，`src/auth/middleware.rs:82`），以 layer 形式挂载（`src/lib.rs:350-354`）。
- Handler 取法全库统一：`Extension(auth): Extension<AuthUser>`（19 个受保护 handler 模块共 108 处，无任何手写提取）。

### 12.3 错误与日志

- 统一返回 `Result<T, (StatusCode, Json<serde_json::Value>)>`。

## 十三、字体与 git-lfs 落地

### 13.1 决策

思源宋体 SC 与思源黑体 SC（各 Regular / Bold，共 4 个字重）**提交入库** `assets/fonts/`，经 git-lfs 托管，换取无外部依赖的确定性渲染；拉丁 / 数学字体用 `typst-assets` 内嵌。代价是仓库体积增加约 60MB。

### 13.2 时序要求（关键，不可逆）

`.gitattributes` 的 LFS 规则**必须先于首次字体提交**生效。二进制一旦被普通 `git add` 提交即永久留存在 `.git` 历史中，后续迁出需 `filter-branch` / BFG 重写历史。

已在 `.gitattributes` 追加：

```gitattributes
# 思源宋体/黑体 SC（约 60MB）—— git-lfs 托管
# 警告：本规则必须先于首次字体提交生效，否则二进制将进入 git 历史，
#       后续迁出需 filter-branch / BFG 重写历史。
assets/fonts/** filter=lfs diff=lfs merge=lfs -text
```

### 13.3 字体完整性校验

未安装 git-lfs 的克隆者只会拿到 132 字节的 pointer 文件（内容以 `version https://git-lfs.github.com/spec/v1` 开头），Typst 加载时**静默失败** → 中文豆腐块，比「字体不入库」更难排查。故提供三平台校验脚本主动拦截：

| 脚本 | 平台 | 说明 |
| --- | --- | --- |
| `scripts/check_fonts.ps1` | Windows PowerShell | 主实现 |
| `scripts/check_fonts.sh` | Linux / macOS Bash | 同逻辑、同退出码 |
| `scripts/check_fonts.bat` | Windows 批处理 | 转调同目录 `.ps1`，对齐 `scripts/` 既有三平台惯例 |

断言（对每个字重）：① 文件存在；② 体积 > 1MB；③ 内容不以 LFS pointer 标识开头。任一失败即输出可操作的修复步骤（`git lfs install && git lfs pull`）并以非零码退出。

### 13.4 兜底

字体文件缺失或损坏时，启动**不报错**，编译时回退 `typst-assets` 内嵌字体，并在预检报告中告警。这是兜底路径，正常部署不应触发——真正的防线是 §13.3 的校验脚本。

> 本节为对正文（§一～§十四）的修正与补充，**冲突处以本节为准**。§15.4 列出已被正文吸收、无需再改的早期评审点。

### 15.1 设计修正（须改）

**R1. 端点职责：删除 `POST /api/v1/typeset/render`**（修订 §四、§3.1、M3）
`/export/pdf` 与 `/typeset/render` 均产出 PDF 且 `ExamRequest.spec` 已允许覆盖默认版面，前端不持有 LayoutDoc、实际只会调用 `/export/pdf`——`/typeset/render` 定位重复。调整为：**PDF 出口唯一化为 `POST /export/pdf`**（mode 默认 spec + 请求内 `spec` 可选覆盖）；`compile_pdf` 保持为模块间函数不暴露 HTTP；`/typeset/preview` 照旧。`handlers/typeset.rs` 相应只含 profiles + preview 两端点。

**R2. MML2OMML.XSL 不直接入库，改为本地引入 + 快照固件入库**（修订 §一、§3.1、§5.3、M2）
该文件随 Office 分发、版权归微软，提交进仓库属再分发，EULA 上有风险。调整为：
- `assets/xsl/MML2OMML.XSL` 加入 `.gitignore`，由开发者从本机 Office 目录（如 `C:\Program Files\Microsoft Office\root\Office16\MML2OMML.XSL`）拷入；
- 仓库只保存**由它生成的黄金快照固件** `tests/snapshots/*.omml`（事实性输出数据，无许可争议）；
- 开发机快照生成脚本入 `scripts/`（需 lxml / xsltproc，仅开发环境）。
同时快照对比的「XML 规范化」须明确三步：**命名空间前缀统一**（lxml 输出与 Word 的 `m:` 前缀写法不同，不改会 CI 误报）→ 属性排序 → 空白归一。

**R3. XML 解析库：读用 roxmltree、写用 quick-xml**（修订 §八）
正文「quick-xml 一库两用，不引 roxmltree」的取舍不成立：事件流上做递归下降转换需手写简易 DOM，成本高于引入 roxmltree（零依赖、只读树，恰适合解析 MathML）。`Cargo.toml` 同时新增 `roxmltree`（读 MathML）与 `quick-xml`（写 OMML/OpenXML），两者皆轻量。

**R4. A3 对折下的逻辑页码为独立实现要点**（修订 §6.3、M4）
`columns(2)` 布局中 typst 的 `counter(page)` 按**物理页**计数，一个 A3 物理页含两个逻辑 A4 页。「第 X 页（共 Y 页）」、动态页眉、奇偶外侧对齐必须基于**逻辑页（左栏/右栏）**实现：自定义逻辑页计数器（每物理页 ×2）+ `place()` 分别落到左右栏 footer 位置；奇偶外侧按逻辑页奇偶判定而非物理页。此项复杂度被正文低估，在 M4 中单列为实现要点并配 typst_gen 结构断言测试。

**R5. 选项防腰斩：`w:tbl` 不可靠，保留 `w:tabs` 制表位降级路径**（修订 §5.4）
Word 中段落 `w:keepNext` 指向**表格**时常不生效，题干→选项表格之间的防腰斩链会断。调整为：M2 先按 `w:tbl` 实现并在 Word/WPS 实测 keepNext 联动；**若失效，选项降级为制表位（`w:tabs`）排在普通段落内**，使 keepNext 链完整。决策记录进 M2 验收清单。

**R6. 字体体积修正与加载方式明确**（修订 §3、§十三）
- 体积估算修正：宋体 + 黑体各 Regular/Bold 共 4 个全量 OTF 约 **90-100MB**（非 60MB），§十三相关表述同步修正；可选瘦身：Source Han **变量字体**单文件（须先验证 typst 对可变字重的实际支持）或 subset。
- 加载方式明确：**运行时读 `assets/fonts/` 目录**注册为 typst Font（与 §6.4 一致），**禁止 `include_bytes!`**——否则二进制膨胀 90MB+、release 构建显著变慢。
- `check_fonts` 脚本阈值（>1MB）同步按变量字体/子集方案复核。

**R7. 选项估宽公式校准**（修订 §6.2）
「公式段按字符数 ×0.55em」对 LaTeX 严重失真（`\frac{a+b}{c}` 源串 12 字符但渲染宽度远小于 12em 位；`\overbrace` 类则相反）。调整为：估宽按**渲染后字形数**折算——剥离命令名、宏参数各计一次、上下标按半宽计入；typst 端保留 `context measure()` 对 Rust 决策做**兜底校验**（估宽判定为 4 列但实测溢出时运行时降 2 列）。决策表单测用例同步改按「渲染字形数」构造。

**R8. 母版分离机制：typst 0.15 无 `page(first:)`，栏数改走容器**（修订 §6.3、M4 T4.9/T4.10）
原任务把首页/正文页分离写成 `page(first:)`，那是 typst ≤0.13 的参数：0.15 的 `PageElem` 字段表里没有 `first`（实测读 `typst-library-0.15.1/src/layout/page.rs`）。0.15 只剩两条母版分离路，实测都不够：flow 中途 `#set page(columns: 2)` 的生效点是**下一页**而非本页；`#page(...)[body]` 作用域会**另起一页**并在结束后回落到外层母版。两者都无法让「通栏卷头」与「同一张纸上的双栏正文」并存——而 A3 对折卷的首页必须同时满足这两件事，否则那张整幅单栏的卷头页在 R4 的逻辑页口径下算 1 页还是 2 页无解，等于推翻 T4.7 已过的门。

调整为：**页级 `columns` 恒为 1，分栏下沉到 `#columns(n, gutter)` 容器**。实测该形成立——通栏卷头块与双栏正文同页共存（第 1 张文字落点 x = 5.0 与 63.0 并存且含通栏块），容器跨页时每一张仍按其栏数分栏，容器结束后正文回到页级单栏宽度。硬约束是 `#pagebreak` 必须留在容器之外（容器内直接报 `pagebreaks are not allowed inside of containers`），故卷结构固定为「通栏卷头 → 正文容器 → 页级 `#pagebreak` → 答案区容器」。栏距与栏数因此从页级 `#set columns` 移入容器参数，R4 的页脚切格不受影响（格宽与容器栏宽同源）。

T4.10 连带修订：「首页不出现页眉」不走母版分离，走条件页眉——`header: context { if here().page() != 1 { … } }` 实测可行（第 1 张无、第 2 张有）。

**R9. 动态页眉机制：`state` 慢一张，改走 `query(metadata)` + `Location.position()`**（修订 §6.3「页眉页脚」、M4 T4.10）
R4 要求动态页眉按**逻辑页（左栏 / 右栏）**走，而 T4.7 已证脚本层问不到「现在是第几栏」。typst 的常规路是 `state`：`header: context { sec.at(here()) }`。实测它取的是**页眉自身位置之前**的状态，也就是「上一张末尾时的大题名」——大题正好起于某张纸顶端时，那张的页眉仍报上一个大题，翻页处慢一张（探针 H3：`update` 落在第 1 张内 → 第 2 张才换）。这条路对「逐张」都做不到，逐栏更无从谈起。

调整为**内省查询 + 绝对坐标反推栏**：

- 每枚大题标题块内嵌一枚 `#metadata(题名)`。`MetadataElem` 是 locatable 元素（实测读 `introspection/metadata.rs`，字段就一个 `value`），零尺寸、不改变版面，题名直接由它的 `value` 携带，Rust 侧不必另存一张表。
- 页眉 `context` 里 `query(metadata)` 逐枚取 `m.location().position()` = `{page, x, y}`（实测读 `introspection/location.rs`）；**x/y 是 length 不是 float**，`.round()` 直接报 `type length has no method round`，只能与 `1mm` / `1pt` 比较或除以 `1pt`。页眉里的 `query` **看得见后面页的标记**（实测第 1 张的页眉打出了落在第 2 张的标记），整条算式因此不必管「取不到未来」。
- 栏索引：`position()` 的 x/y 是**页内绝对**坐标，与帧树 `PlacedRun.x_mm/y_mm` 同一原点（实测 120mm 页 / 5mm 边距：标记落在 x=14.17pt=5mm=该页左边距，`columns` 容器里两栏正文帧 x=5.0 / 63.0 正是两栏左沿）。栏左沿由 Rust 从同一套几何算出（`margin_left_mm()` / `column_width_mm()` / `column_gutter_mm()`，typst 与测试共用 [`column_lefts_mm`](../src/typeset/spec.rs)），传进模板的是「首栏左沿 + 栏步长」两个数，`c = xs.filter(v => q.x + 1pt >= v).len() - 1`。标记埋在两层 `block` 里仍可查询、位置就是它自己（探针 H2）。
- 归属规则是**本栏覆盖最长**：上一条标记管到本栏首枚标记（本栏一枚标记都没有就管到栏底），本栏每枚标记管到下一枚或栏底，取覆盖最长的那一条。放弃「文档序里最后一个 `(page, col) ≤ (本页, 本栏, 版心上沿)`」那一版：`section-header` 自带 `above: 8pt` 与 `inset: y: 3pt`，栏顶那枚标记实测落在版心上沿下方 3.8mm（top=22 → y=25.8；top=18 → y=21.8），容差得写成一枚魔法常数；而「这一栏谁占得多」本来就是页眉要说的话。
- 页眉格与页脚格同一套切法（`grid(columns: range(n).map(_ => 1fr), gutter: (栏距, 0pt), ..cells)`，格宽与容器栏宽同源），实测格与栏对得上：对折卷栏沿 16 / 220、栏宽 184，两格文字起于 x=100.1 / 304.1（= 两栏中心各减半枚题名宽）。栏数取 `spec.columns`（内容口径），与页脚取 `logical_slots()`（页码口径）分属两件事。
- typst 侧现造列表的三条雷（逐条实测报错）：`array(1mm)` 是**类型转换**不是构造器（`expected array, bytes, or version, found length`）；单栏写成 `(18mm)` 只是一个 length 而不是元组（`type length has no method filter`）；`repeat(2, 1fr)` 第一枚位置参数要 content（`expected content, found integer`）。只有 `range(n).map()` 在两种栏数下都给 Array。
- 首页仍走 R8 的条件页眉整张关掉；`header_footer.header_title` 仍是总开关。
- 代价：每页一次 `query` + 每标记一次 `position()`（typst 文档明说 `position()` 比 `page()` 多做事）。实测 A3 对折 3 张仿真卷：关页眉中位 123ms、开页眉中位 123ms（同进程首编 14.9s 是字体扫描的一次性开销，两边都有）——大题名 2–6 枚这个量级下不必计这条开销。

**R10. 公式编号的号在 Rust 侧数，typst 只负责排版**（修订 §6.3「公式编号」、M4 T4.11）
计划原文写的是「自定义计数器」，落地改成 Rust 侧计数 + `#equation(号)[式子]`，三条理由：

- **「降级的那枚不占号」只有转换那一刻知道**：`to_typst` 返回 `Err` 时这枚公式根本进不了 `#equation`，typst 侧的 `counter` 看不见没落地的东西，也就无从「不占」。
- 生成顺序即版面顺序：`Gen` 单趟铺块，选项栅格里的 `measure` 量的已经是生成好的内容、不重跑生成（实测过这条，见 T4.2），所以 Rust 数出来的序与 typst 走出来的序是同一个。
- 号是常量字符串，源码级断言（`(1.1)`/`(1.2)`/`(1.3)`/`(2.1)`）比 `context` 里的计数器可读，也不必为它多开一层 `set` 作用域。

范围口径：只有**属于某个大题的正文**（题干 / 选项 / 提示框 / 讲义模式内嵌的解析）编号，`Gen::body` 每进一个大题重置一次；**卷末答案区整段不编号** —— 那一页不归任何大题管，挂上前一个大题的号只会指错地方。降级公式（红色等宽原文）不占号。
版面：`#equation(no, body)` 是三轨网格 `(1fr, auto, 1fr)`，式子按**所在内容盒**居中（题目里就是悬挂缩进后那一盒，实测中心 110 而非栏中心 105），号贴本栏右沿（实测 `(1.1)` 起于 x=185.4，版心右沿 192）。`$…$` 落进网格单元仍是行间口径（实测求和号的上限悬在正上方 103.5/106.5，不是右上角）。

**R11. K100 是「前景转黑、底纹退白」的门控；docx 的纸张从 `LayoutSpec` 现算**（修订 §6.3「PrintBlackOnly」、§7 docx 段、M4 T4.12）

⛔ 原文「`PrintBlackOnly`：全文 `luma(0%)`」不能字面执行：大题条的 `fill: luma(236)` 与提示框底色一起转黑就是黑底黑字，整段内容消失。定口径为**分治**：

- **前景**（文字、线、点阵、公式编号、降级原文）→ `black`；**底纹**（区块 fill、表格底纹）→ 白（`luma(100%)`）。这与 T4.6 已有的 callout 纯黑处理（`("luma(0%)", "luma(100%)")`）是同一条口径，只是把散落的硬编码灰纳入。
- 落地位置：`#let ink(c)` / `#let tint(c)` 两枚函数排在 `PAGE_FURNITURE` **之前**（紧随 `MITEX_PREAMBLE`），由 Rust 按 `spec.color` 生成。放不进母版是 T4.7 那枚老坑的重演 —— `#set page(header:, footer:)` 的参数在写下那一刻就求值，页眉页脚看不见其后任何 `#let`（实测把调色板挪到母版之后就报 `unknown variable: ink`），而恰恰是页脚格、装订带、动态页眉这三处的灰最需要门控。函数体因此只有一句 `black` 或原色，模板里所有灰阶写成 `ink(luma(110))` / `tint(luma(236))`，彩色模式恒等、单色模式一处收口。
- **降级红色也归 `ink()` 管**：`rgb("#B00000")` 在 K 版分离下近乎 0% 黑，「红色原文」印到单色卷上等于把那道公式印成空白。它是给人眼与警告清单看的信号，单色卷上必须仍是可见的黑字。
- 验收口径从「源码里不许出现灰阶」改成「**编译产物的拾色集合**只含黑白」：typst 的 SVG 把颜色落成 `fill="#rrggbb"`（实测对折样卷里出现 `#5a5a5a` / `#6e6e6e` / `#787878` / `#b26a00` / `#fff5e6`），门是同一份 IR 编两次 —— 单色卷的 fill/stroke 集合 ⊆ 黑/白/none，彩色卷的集合必须严格更宽。源码级断言会漏：`ink(luma(110))` 里那串灰仍然在源码里，只是不再上纸。

docx 侧的纸张同步（T4.12 另一半，原文只写了「`sectPr` 按 `spec.paper` 输出」）：

- `A4_SECT_PR` 常量退役，`sectPr` 由 `LayoutSpec` 现算：`w:pgSz`（mm→twips，宽>高时补 `w:orient="landscape"`，Word 不会自己转）、`w:pgMar` 四边取 `margins`，**`w:left` 存声明值、装订带另记 `w:gutter`**（Word 的生效左边距 = 两者相加，正好等于 PDF 侧的 `margin_left_mm()`：A3 三栏 `Left` 卷 `w:left=794`（14mm）+ `w:gutter=1134`（20mm 带）= 生效 34mm）、`w:cols w:num/space` 取 `columns` / `column_gutter_mm()`。
- **正文可用宽改成算出来的**：原先 `TEXT_TWIPS = 9070` 与 `A4_SECT_PR` 之间只有注释上的一句「同源」，卷头表、分值表、选项栅格、图片上限全用这个常量。现在宽度 = 页宽 − 生效左右边距 − `w:gutter`，且**分栏时按栏宽**（Word 的 `w:tblW/@w:dxa` 是相对所在栏的，用整幅宽写会把表格顶出栏外）。
- `spec` 走 PDF 同一个 [`resolve_spec`](../src/export/pdf.rs)，字段级覆盖语义两边一致。
- 三处口径差异**不抹平**，写进 docx 边界：① Word 的 `w:cols` 是平衡栏且页码按**张**计，与 R4「A3 对折半张 = 一页」不是一回事，同一份 A3 对折卷两边页数差一倍；② `CenterFold` 的 20mm 折痕带在 docx 没有落点（`w:gutter` 只有装订侧一个概念），`binding_gutter_mm()` 恒 0，那 20mm 由 `column_gutter_mm()` 的下限转成 `w:cols w:space=1134`（对折卷实测）—— 折痕没了、总宽不亏；只有 `Left` 映射成 `w:gutter`；③ 密封线上的竖排考生信息在 docx 恒退化为首页横排信息表（T4.9 既有结论）。

三条由此而来的调优口径：

1. **R7 的 measure 阶梯按「离阈值多远」决定付不付钱**。`choice_grid::decide` 的判据是 `最宽选项 / 可用栏宽 ≤ 0.25 / 0.50`，阈值本身不带余量，贴着阈值才真的需要 typst 复量。现在由 Rust 把结论传进模板：`#choices(列数, probe: true/false, boxed: true/false, …)` —— 最宽选项估宽 ≤ **85%** × 单列预算（`(栏宽 − 悬挂缩进 − (列数−1)×间距) / 列数`）⇒ `probe: false`，一枚都不量。这一枚开关买的是 **≈20–30ms/行**（复量一行四选项的实测单价，四轮读数，见本节末），十行混合卷就是 200–300ms。
2. **贵的是 `grid` 本身，不是那趟复量：选项行只留一种画法**。同一批 40 枚选项单元格，排成 `grid` 要 **1025ms**，排成定宽 `box` 只要 **109ms**，而空卷（只有模板）的地板是 117ms（调优前的读数；今日同一探针读到 91–96ms，取本轮的数）—— 免量那侧十道题**等于不要钱**。同一份源码只换渲染器的 A/B 是 1050ms → 470ms。算下来 **一枚 `grid` 单元格 ≈ 14–22ms**，是它上面那趟 `measure`（4.5ms）的三到五倍。所以 `probe` 与 `boxed` 两枚开关都只改「列数怎么定」，行一律画成 `par` + `box(width: 100% / n)`（`boxed: false` 那一侧除外，见第 3 条）。
3. **`boxed: false` 是唯一保留 `grid` 的一侧**：单元格里有表格 / 硬换行 / 并排图组 / 块级公式（进了 inline block 会改分页与显示样式语义），或有图片（宽高比要解码才知道，是**宽度**唯一会系统性低估的一类）。那一侧与 R13 之前逐字相同 —— 免量与换画法都只发生在 Rust 能证明「这枚单元格装得进本列、必然单行」的地方，与 T4.5 `keep-together` 同一个哲学：**开关不是省钱的，是「已证安全」与「未证安全」的分界**。

**顺带修掉一个版面缺陷**（本条的断言最初写反了，是被实测纠正的）：`grid` 包在 `layout(size => …)` 里会把整行收成**内容宽**而不是铺满容器 —— 两列实测档距 34.28mm，铺满该是 38.2mm；三栏卷上「四列挤在左半截、间距 12.16 / 10.94 / 11.12mm 不等距」就是同一病灶的极端形态。`box(width: 100% / n)` 是精确分数，等距且铺满，与 docx 的等宽 `w:tblGrid` 同一个口径。收缩本身在 `boxed: false` 那一侧仍在（与性能无关，本批次不修，另开一轮）。

`choices` 模板上原先那句「实测 113ms 对 114ms，500ms/卷的预算很宽」是 debug 且未 evict 的读数，作废。`cost_of_the_measure_fallback` 的对照组重做过两次才立住：第一次拿「把所有题判成单列」当对照，而单列只留一种画法之后连版面长度都变了（兜底 3 页 对 单列 4 页，差值成了负的 56ms —— 把页数差读成兜底单价）；第二次改成在仿真卷源码里翻 `probe: true`，翻到的却是模板定义那一行的默认值（`sim_doc` 在 a4_practice 下一枚都不复量，调用点全部逐字传参），两组源码逐字相同仍报出差 125ms —— 这一跤把**这把尺子的噪声底**顺手量了出来。现在是最终形态：同一份前言 + 20 行合成四选项（每枚 ≈9.4em，两种取值都排得进四列），只翻调用点的 `probe`，页数相等升级为断言，5 轮 evict 冷编取中位。读数（同日四轮，每轮两组各 5 次 evict 冷编取中位）：**兜底开 1173 / 1655 / 1548 / 1289ms 对 全免量 759 / 1047 / 950 / 835ms，四组都同为 4 页 ⇒ 差 414–608ms、复量一行四选项 ≈20–30ms（每枚 5–7ms）**。绝对值整档随机器负载漂移（同一轮里两组都跟着抬），能用的是差值——四轮都越过噪声底三倍，可以当归因用；单价因此记成区间而不是一个点。

**百页那道门的重述**（2026-09-03 裁决采纳，落定口径见上面「门的处置」）：`101 页 = 400 题 × 6.4ms + 地板 + 页家具` 实测 **2521 → 2524ms**，本轮调优一分未动（那份卷子一道多列选择题都没有），**在不改内容量的前提下不可达**，能压的只有内容项数量。定稿为「≤80 页 ≤2s（实测 1909 → 1927ms ✓）+ 百页走热请求（实测 99ms）」，百页冷编 2.5s 是**已知不达标项**而不是一个还没人去够的常数。

### 15.2 边界补充（正文未覆盖的场景）

**B1. 外链图片**：题干图片白名单允许 `https://` 外链。docx/typst/pdf 均需处理：reqwest 拉取（复用现有依赖，**超时 5s + 体积上限 10MB + 格式嗅探**），失败或超限则跳过并记入警告/Issue；Markdown 路径保留原 URL 不拉取。
**B2. 填空题挖空**：学生卷中填空题若 stem 已含 `______` 直接沿用；若答案内嵌 stem（少见形态）则按 `correct_answer.blanks` 挖空为等长下划线。M1 装配器实现，附单测。
**B3. `X-Export-Warnings` 头上限**：HTTP 头经代理默认 ~8KB 限制。警告序列化后超限时**截断并附 `truncated: true` 标记**，前端提示「完整清单请用预览接口查看」。
**B4. 前端超时**：`client.ts` 全局 `timeout: 10000` 对百页大卷（编译 ≤2s + 大 blob 下载）可能触顶。`exportApi`/`typesetApi` 单独设 `timeout: 60000`。
**B5. 留白双字段职责**：`options.answer_space`（导出语义：是否留白 + 高度）与 `LayoutSpec.answer_blank`（渲染样式：横线/点阵/空白）字段重叠。明确映射：**适配器合并二者**——`options.answer_space` 优先决定开关与高度，`spec.answer_blank.style` 决定样式，二者冲突时以 `options` 为准并记 info 日志。
**B6. 前后端类型同步**：`LayoutSpec`/`ExamRequest` 结构复杂，前端手写 TS 类型必然漂移。引入 **ts-rs**（或 specta）从 Rust struct 自动导出 `frontend/src/api/types/`，纳入 M1（先覆盖 ExamRequest，M3 补 LayoutSpec）。
**B7. SVG 预览注入防御**：typst 输出 SVG 本身无脚本，但 `v-html` 直接注入仍属危险模式。`TypesetPreview` 对返回 SVG 做基础 sanitize（剥 `<script>`/事件属性）或以 `iframe sandbox` 承载，写入 M5 验收项。
**B8. 「保存组卷」显式出界**：`Basket.vue` 的 `savePaper` 占位（落 papers/paper_questions 表）**不属于本计划范围**，列为后续独立需求，防止执行时范围蔓延。

### 15.3 风险预案与验收修订

**P1. latex2mathml 覆盖率预扫描**：该 crate 为 0.2 轻量库，对 `\begin{cases}` / `\begin{aligned}` 等教辅高频环境支持存疑。M2 第一步先对**现有题库全量 stem 做预扫描**（仅跑 latex2mathml 统计失败率）：降级率 >5% 即启动备选评估——前端 KaTeX `output:'mathml'` 预转换随请求上传，或引入 temml；≤5% 则按计划继续并记录基线。
**P2. 性能指标分冷热表述**：预览每次 `main.typ` 全变，comemo 增量主要缓存字体/库层，收益有限。验收口径改为两层：**冷编译**（同参数首次，typst 实测：单卷 ≤500ms / 百页 ≤2s）与**热请求**（LRU 命中直接返回缓存字节，毫秒级）。原「二次编译命中缓存显著更快」的模糊表述作废。→ **「收益有限」被 R13 实测推翻**：comemo 覆盖的正是请求级整文档布局，热请求 16–100ms；「热请求」那一层不需要新的 LRU，需要的是给 comemo 一个容量上界（`comemo::evict`）。「单卷 ≤500ms / 百页 ≤2s」两个常数按 R13 的成本模型重述 → **已裁决（2026-09-03）**：`≤80 页 ≤2s` + 百页走热请求（百页冷编 2.5s 记为已知不达标项），混合 20 题卷那道 500ms 降为 ≤700ms 回归哨兵——超出的 174ms 是「保留贴阈值复量」的代价，裁决不买。
**P3. 基准形式**：性能基准定为 `#[ignore]` 的 cargo 测试（`cargo test -- --ignored` 生成报告），不引入 criterion；样本为 20 题仿真卷 + 构造的 100 页大卷。
**P4. typst 依赖树构建成本**：typst 全家桶约 200+ crates，M3 合入后首次 `cargo build` 显著变慢属预期；验证清单增加「dev profile 与 release profile 各构建一次」。
