## 1. 项目背景与目标

### 1.1 背景

初中及高中数学教学过程中，教师日常需要大量题目用于课堂练习、课后作业、阶段测验、期中期末考试。题目分散在个人文档中，缺乏统一管理、缺乏质量审核、缺乏跨年级协同。

### 1.2 目标

构建一个**多教师协同的题库系统**，实现：

- 题目统一存储、分类、检索
- 多人协作编辑 + 审核发布流程
- 结构化知识点分类体系
- 支撑组卷出题（手动/智能）
- 版本可追溯，内容可审核

### 1.3 范围

| 纳入范围 | 不纳入范围（v1） |
|----------|-----------------|
| 初中数学（7-9 年级） | 在线考试/答题系统 |
| 高中数学（10-12 年级） | 自动批改 |
| 选择题 / 填空题 / 解答题 / 判断题 | 学生端 App |
| 空间内协作 + 灵活审题流程 | 学情分析 |
| 知识点树维护 | 智能推荐算法 |
| 组卷功能 | OCR 识别纸质题 |
| 公共题库双向流通（复制） | 跨空间引用同一实体 |

## 2. 系统角色与空间模型

> v0.2 起，权限不再由「固定全局身份」决定，而由 **空间归属 + 空间内协作规则** 决定。

### 2.1 系统级角色（刻意极简）

| 角色 | 作用 |
|------|------|
| **User** | 普通用户：拥有 1 个个人空间，可创建/加入团队空间，可贡献至公共库 |
| **Admin** | 平台管理：用户管理、公共库治理（下架等）、运维 |

**已移除**：`GroupLeader` / `Teacher` / `Viewer` 全局角色。历史数据中这些角色在迁移时统一映射为 `User`，仅 `admin` 保留。

> 注：「谁能审题」不再由全局角色决定，而由 §5 的空间规则决定。

### 2.2 三种空间

```text
                    ┌─────────────────┐
                    │  公共题库空间    │  全站共享，已发布题目
                    │   (Public)      │
                    └────────┬────────┘
               贡献↑         │         ↓导入（复制）
        ┌──────────┴─────────┴──────────┐
        │                               │
 ┌──────▼──────┐                 ┌──────▼──────┐
 │ 个人题库空间 │                 │ 团队题库空间 │
 │ (Personal)  │                 │  (Team)     │
 │ 自己录自己审 │                 │ 成员协作    │
 └─────────────┘                 └─────────────┘
```

| 空间类型 | 用途 | 谁可写 | 审题方式 |
|----------|------|--------|----------|
| **Personal** | 教师私有题库 | 仅所有者 | 默认创建者可自审（`allow_creator_self_review=true`） |
| **Team** | 团队协作题库 | 空间成员 | 创建者回避 + 团队其他成员可审 / 指定审题人 |
| **Public** | 全站共享题库 | **不可直接写**，仅通过「贡献」流入 | 无审核流程 |

约束：
- 每个用户注册时自动创建 1 个 `personal` 空间（由 `ensure_personal_space` 保证）
- 全站仅有 1 条 `public` 空间（启动时由 `ensure_public_space` 保证，固定 UUID `00000000-0000-0000-0000-000000000001`）
- 历史无 `space_id` 的题目在迁移时挂到创建者的个人空间；无创建者则挂到公共空间

### 2.3 团队空间成员

| 字段 | 说明 |
|------|------|
| `space_id`, `user_id` | 联合主键 |
| `role` | `owner`（空间创建者，可管理成员）/ `member`（普通成员） |
| `duties` | `text[]`：`{entry, review, analysis}` 职责标签（**首期不强制**，详见 §5.4） |
| `joined_at` | 加入时间 |

> 团队中录入与审查角色**可轮流替换**，无固定分工。`duties` 字段保留以备后期软过滤，首期不展示 UI。

## 3. 题目实体

### 3.1 字段定义

```text
题目 (Question)
├── id              : 全局唯一标识
├── stem            : 题干（支持 LaTeX / 富文本）
├── question_type   : enum { choice, fill, solution, judgment }
├── difficulty      : enum { easy, medium, hard }
├── default_score   : 默认分值（正整数）
├── status          : enum { draft, pending, rejected, published, disabled }
│
├── options         : 选择题选项 [{label, content}]
├── correct_answer  : 按题型不同结构（见 3.2）
├── analysis        : 详细解析（富文本 / LaTeX）
├── grading_criteria: 解答题分步评分
│
├── knowledge_points: [知识点 ID] — 多对多关联
├── grade           : 适用年级
├── semester        : 学期
├── source          : 来源说明
│
├── space_id        : **所属空间**（NOT NULL）
├── origin_question_id : 从公共/其他空间复制时的来源题目 ID（可空）
│
├── creator_id      : 创建者
├── created_at      : 创建时间
├── updated_by      : 最后编辑者
├── updated_at      : 最后编辑时间
└── version         : 版本号（单调递增）
```

> 与 v0.1 相比，新增 `space_id`（必填）与 `origin_question_id`（可空，用于公共库流通追溯）。

### 3.2 题型特定结构

#### 选择题 (choice)
```text
- options: [{ label: "A", content: "..." }, ...]
- correct_answer: "A"  // 单选
```

#### 填空题 (fill)
```text
- blanks: [{ position: 1, answer: "…" }, ...]
```

#### 解答题 (solution)
```text
- correct_answer: "完整解答"
- grading_criteria: [{ step, points }, ...]
```

#### 判断题 (judgment)
```text
- correct_answer: true / false
```

### 3.3 题目生命周期

```text
     ┌──────────┐
     │  draft    │ ◄──── 创建者录入
     └────┬─────┘
          │ submit（可指定审题人）
          ▼
     ┌──────────┐
     │ pending   │
     └────┬─────┘
         ╱ ╲
        ╱   ╲
       ▼     ▼
  ┌──────────┐ ┌──────────┐
  │published │ │ rejected │
  └────┬─────┘ └────┬─────┘
       │          │ 重新编辑（生成新版本）
       │          ▼
       │     ┌──────────┐
       │     │  draft   │
       │     └──────────┘
       │ Admin 下架
       ▼
  ┌──────────┐
  │ disabled │
  └──────────┘
```

**状态规则：**

| 状态 | 谁可编辑 | 谁可见 | 可否用于组卷 |
|------|----------|--------|-------------|
| draft | 创建者 / 空间 owner / Admin | 空间成员 | ❌ |
| pending | 无人（只读锁定） | 空间成员（只读） | ❌ |
| rejected | 创建者 / 空间 owner / Admin | 空间成员 | ❌ |
| published | 无人（只读） | 视空间可见性（详见 §5.1） | ✅ |
| disabled | 无人（只读） | 同上（标记停用） | ❌（已有引用不受影响） |

### 3.4 版本控制

- 每次编辑保存都作为**一个版本**记录
- 已发布的题目如需修改：创建者创建新版本（回到 draft 状态），走重新审核
- 旧版本永远可追溯

## 4. 知识点分类体系

### 4.1 知识点树（v1）

```text
数学 (root)
├── 数与代数
│   ├── 有理数 / 实数
│   ├── 代数式（整式 / 分式）
│   ├── 方程与不等式
│   ├── 函数（一次/二次/反比例）
│   └── 数列 (高中)
├── 图形与几何
│   ├── 三角形 / 四边形 / 圆
│   ├── 图形变换
│   ├── 三角函数 (高中)
│   ├── 向量 (高中)
│   └── 立体几何 (高中)
├── 统计与概率
├── 综合与实践
└── 竞赛专题
```

### 4.2 管理规则

- 知识点为**树形结构**，最多 4 层深度
- 一道题可关联 **1~5 个**知识点标签
- 知识点树**首期仍全局共享**（不按空间隔离）；二期可按空间拆分
- 维护权限：Admin 与任意空间 owner 均可（首期不细分）

## 5. 空间内协作与审题流程

### 5.1 空间可见性

| 空间类型 | 题目可见性 |
|----------|-----------|
| Personal | 仅所有者 |
| Team | 空间成员 |
| Public | 任意登录用户 |
| Admin | 可查看所有空间（治理） |

### 5.2 编辑权限

`can_edit_question(user, q)` 判定（集中在 `src/auth/permissions.rs`）：

1. 状态非 `draft` / `rejected` → 否
2. Admin → 是
3. 不在空间写权限内 → 否
4. 创建者本人 → 是
5. 团队空间 owner → 是（协助编辑）
6. 其他 → 否

### 5.3 审题规则（核心）

`can_review_question(user, q)` 判定顺序：

1. 题目状态非 `pending` → **否**
2. Admin → **是**（运维）
3. **指定审题人非空** → 用户必须在 `question_reviewers` 列表中
4. **个人空间** → 创建者本人可自审（`allow_creator_self_review` 默认 true）
5. **团队空间**：
   - 必须是空间成员
   - 若 `require_review_duty=true` → 必须有 `review` 职责（首期默认 false）
   - **创建者回避**（硬编码）：`creator_id == auth.id → 否`
   - 其他成员 → 是
6. **公共空间** → 否（公共库无审核流程）

> **关键设计决策（v0.2）**：
> - 个人使用场景：录入人可自行审核发布，无需他人介入
> - 团队协作场景：录入题目的人**不能审自己录入的题**，必须由团队其他成员审
> - 团队成员可轮流担任录入 / 审查角色，无固定职责分工

### 5.4 三种使用场景

| 场景 | 空间 | 审题方式 |
|------|------|----------|
| **个人使用** | 个人空间 | 录入人可自行审核/发布 |
| **团队分工** | 团队空间 | 成员可轮流录入/审查；审查者不能是创建者 |
| **指定审题** | 团队（或个人） | 创建/提交时指定 1～N 个审题人，仅他们可审 |

三种方式可并存，**优先级**：指定审题人 > 空间默认规则。

### 5.5 单人编辑锁

- 教师打开题目编辑时加**悲观锁**
- 加锁后其他教师只能**只读查看**
- 编辑超过 30 分钟无操作 → 锁自动释放
- 教师主动关闭编辑器 → 释放锁

> 注：v0.2 当前实现未启用悲观锁，留待后续迭代。

### 5.6 通知机制

| 事件 | 通知谁 | 通知方式（v1） |
|------|--------|----------------|
| 题目提交审核 | 指定审题人 / 团队其他成员 | 站内消息（待实现） |
| 审核通过 | 创建者 | 站内消息（待实现） |
| 审核驳回 | 创建者 + 驳回原因 | 站内消息（待实现） |
| 题目被停用 | 创建者 | 站内消息（待实现） |

## 6. 公共题库流通（v0.2 新增）

### 6.1 复制语义（首期）

| 操作 | 行为 |
|------|------|
| **贡献到公共** | 空间内已发布题 → **复制**一条到 public 空间（新 id，记 `origin_question_id`） |
| **从公共导入** | public 已发布题 → **复制**到个人/团队空间（新 id，记 `origin_question_id`） |

采用**复制**而非引用，避免公共改动污染私有卷/试卷；二期可做「链接引用」。

### 6.2 权限

- `can_contribute_to_public`：空间成员 + 题目已 `published`
- `can_import_from_public`：目标空间成员
- Admin 可对公共题下架（`disabled`）

## 7. 组卷功能

### 7.1 手动组卷

1. 教师新建试卷，设定标题、考试类型（周测/月考/期中/期末/作业）
2. 设定试卷结构：题型分布、题量、总分
3. 从题库按条件检索题目，逐题添加到试卷
4. 调整题目顺序，每道题可独立设置**分值**（覆盖默认值）
5. 保存为草稿 / 发布 / 导出

### 7.2 自动组卷（简易版 v1）

1. 教师输入参数：题型 × 道数、知识点范围、难度分布、总分
2. 系统按条件从**已发布**题库中抽样
3. 生成试卷草稿，教师可手动调整

### 7.3 试卷实体

```text
Paper (试卷)
├── id
├── title
├── subject
├── grade
├── total_score
├── duration_minutes
├── status       : enum { draft, published, archived }
├── questions    : [{ question_id, sort_order, score, section }]
├── creator_id
├── created_at
└── updated_at
```

> 试卷本身不绑定空间，但只能引用已发布题目（来自当前空间或公共库）。

## 8. 搜索与检索

### 8.1 题目搜索条件

- 关键词（模糊匹配题干）
- 题型 / 难度 / 年级
- 知识点（树形选择，含子树搜索）
- 状态
- 创建者
- **空间过滤**（默认当前选中空间）
- **`reviewable_by_me=1`**：返回当前用户可审的 pending 题（用于审核队列）

### 8.2 搜索结果

- 列表展示：题干摘要 + 题型 + 难度 + 状态 + 创建者 + 创建时间
- 可点击进入详情
- 支持多选（用于批量审核、批量添加至试卷）

## 9. 非功能需求

| 需求 | 说明 |
|------|------|
| LaTeX 渲染 | 题干、解答中的数学公式支持 LaTeX 语法（KaTeX） |

| 访问控制 | **空间归属 + 空间内协作规则**双重校验（集中 in `src/auth/permissions.rs`） |

## 10. 数据关系概览（ER 核心）

```text
Users ──1:N──> Spaces (owner)         ── 个人/团队空间所有者
Users ──M:N──> Spaces (space_members) ── 团队成员
Spaces ──1:N──> Questions             ── 题目归属
Questions ──M:N──> KnowledgePoints
Questions ──1:N──> QuestionReviewers  ── 指定审题人
Questions ──self──> Questions (origin_question_id) ── 公共库复制来源

Papers ──M:N──> Questions (PaperQuestion)
Papers ──> Users (创建者)
```

### 关键表

| 表 | 用途 |
|----|------|
| `users` | 用户，role ∈ {admin, user} |
| `spaces` | 题库空间，kind ∈ {personal, team, public} |
| `space_members` | 团队成员（含 role / duties） |
| `questions` | 题目，含 `space_id`、`origin_question_id` |
| `question_reviewers` | 指定审题人 |
| `knowledge_points` | 知识点树 |
| `papers` / `paper_questions` | 试卷与题目关联 |

> 已移除：`groups` / `group_members`（v0.2 由 `spaces` + `space_members` 替代）

## 11. 权限判定集中点

所有权限判定集中在 `src/auth/permissions.rs`：

| 函数 | 用途 |
|------|------|
| `is_admin(role)` | 系统管理员校验（大小写不敏感） |
| `ensure_personal_space` | 注册时创建个人空间 |
| `ensure_public_space` | 启动时确保公共空间存在 |
| `can_access_space` | 空间可见性 |
| `can_write_in_space` | 是否可在空间内创建/编辑题目 |
| `can_edit_question` | 是否可编辑该题（草稿/驳回 + 创建者或 owner） |
| `can_review_question` | 是否可审核（三种场景 + 创建者回避） |
| `list_reviewers` | 指定审题人列表 |

前端通过 `GET /questions?reviewable_by_me=1` 与 `QuestionDetail.can_review` 字段获取权限提示，**最终以后端判定为准**。
